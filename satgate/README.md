# دروازه‌ی ماهواره (satgate)

سرویس کوچکی که **روی یک سرور خارج از ایران** اجرا می‌شود و کار سنگین تصویر ماهواره‌ای را انجام می‌دهد:
جست‌وجو در کاتالوگ STAC (Earth Search، رایگان و بدون ثبت‌نام)، خواندن **فقط تکه‌ی لازم** از تصویرهای COG،
ساخت محصول (رنگ طبیعی، فروسرخ کاذب، NDVI، همه‌ی باندها، DEM) و تحویل فایل برش‌خورده به پنل.
سرور ایران فقط دستور می‌دهد و فایل آماده را برمی‌دارد؛ GDAL آن همچنان از اینترنت جداست.

```
پنل (ایران) ──امضا HMAC──► دروازه ──► Earth Search / S3
     ▲                        │ برش و ساخت محصول (≤ چند ده مگابایت)
     └── هوک «آماده شد» ◄─────┘   (اگر نرسید، پنل هر دقیقه وضعیت را می‌پرسد)
     └── دانلود فایل (Range) ─► پنل ← gdalinfo + تبدیل به COG ← حذف از دروازه
```

## نصب (روی سرور خارجی)
۱. Docker نصب کنید و ایمیج را بگیرید (یا `docker build -f satgate/Dockerfile -t satgate .` از ریشه‌ی مخزن).
۲. کلید مشترک بسازید:
```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```
۳. `satgate/.env.example` را به `.env` کپی و پر کنید، سپس:
```bash
docker compose -f satgate/docker-compose.yml --env-file .env up -d
```
۴. جلوی پورت ۸۰۸۰ یک پراکسی با TLS بگذارید (مثلاً دامنه‌ی `sat.example.com`). بهتر است فایروال فقط IP سرور ایران را بپذیرد.

## تنظیم پنل (سرور ایران)
نیازی به Coolify یا اجرای دوباره‌ی سرویس نیست؛ همه‌چیز از داخل خود سایت تنظیم می‌شود:

۱. پنل مدیریت ← **تنظیمات سایت** ← زبانه‌ی **ماهواره**.
۲. **نشانی دروازه‌ی ماهواره** را بنویسید، مثلاً `https://sat.example.com` (همان نشانی که پراکسی HTTPS سرور خارجی دارد).
۳. **کلید مشترک:** یا کلیدی را که روی دروازه به‌عنوان `SATGATE_SECRET` گذاشته‌اید وارد کنید، یا «ساخت کلید تصادفی تازه» را بزنید؛ کلید یک‌بار بعد از ذخیره نشان داده می‌شود تا آن را روی دروازه بگذارید (و دروازه را دوباره بالا بیاورید).
۴. **ذخیره** کنید، سپس **آزمایش اتصال به دروازه** را بزنید. این آزمون چهار چیز را می‌سنجد: در دسترس بودن دروازه از سرور ایران، درستی کلید، دسترسی دروازه به کاتالوگ و داده‌ی ماهواره، و سرعت دانلود به ایران.

کلید رمزنگاری‌شده ذخیره می‌شود و دوباره نمایش داده نمی‌شود. تا نشانی و کلید خالی است، بخش «تصویر ماهواره‌ای» برای کاربران «به‌زودی» نشان داده می‌شود.
اگر به ترمینال دسترسی دارید، همان آزمون با `python manage.py sat_probe` هم اجرا می‌شود. متغیرهای محیطی `SATGATE_URL` و `SATGATE_SECRET` فقط جایگزین‌اند و وقتی تنظیمات سایت خالی باشد خوانده می‌شوند.

## عیب‌یابی: «امضا پذیرفته نشد»
دکمه‌ی «آزمایش اتصال» و لاگ دروازه (`docker compose … logs`، خط `rejected …`) علت را دقیق می‌گویند:

| علت | معنی | راه‌حل |
|---|---|---|
| `skew` | ساعت پنل و دروازه بیش از ۲ دقیقه اختلاف دارد (اختلاف به ثانیه نوشته می‌شود) | ساعت هر دو سرور را با NTP همگام کنید (`chronyc makestep`) |
| `key` | کلید دو طرف یکی نیست | همان کلید را در تنظیمات سایت و `SATGATE_SECRET` بگذارید و دروازه را با `--force-recreate` دوباره بسازید |
| `signature` | کلیدها یکی‌اند ولی امضا نخورد | پراکسی یا CDN مسیر یا بدنه را عوض می‌کند؛ نشانی دروازه را بدون مسیر اضافه بدهید |
| `no_secret` | روی دروازه کلیدی تنظیم نشده | `SATGATE_SECRET` را در `.env` بگذارید |

## منبع‌ها و تأمین‌کننده‌ها
فهرست کامل (کد: `satgate/spec.py`؛ مرجع تنها یک جاست و پنل هم از همان می‌خواند). هر ماهواره یک یا چند **منبع** دارد؛ اگر تأمین‌کننده‌ی اول خطا بدهد یا چیزی نداشته باشد، بعدی امتحان می‌شود.

| منبع (کلید) | تأمین‌کننده | حساب |
|---|---|---|
| Sentinel-2 L2A (`sentinel2`) | Earth Search، پشتیبان: Planetary Computer | ندارد |
| Sentinel-2 Collection-1 (`s2_c1`) و L1C (`s2_l1c`) | Earth Search | ندارد |
| Landsat 8/9 (`landsat`) و Landsat 4/5/7 از ۱۹۸۲ (`landsat_old`) | Planetary Computer (توکن کوتاه‌مدت را دروازه خودش می‌گیرد) | ندارد |
| Sentinel-1 RTC رادار (`s1_rtc`) | Planetary Computer | ندارد؛ دسترسی را «آزمایش اتصال» می‌سنجد |
| ارتفاع Copernicus ۳۰ و ۹۰ متر (`dem`، `dem90`) | Earth Search، پشتیبان: Planetary Computer | ندارد |
| NASADEM (`nasadem`)، ALOS AW3D30 (`alosdem`) | Planetary Computer | ندارد |
| ESA WorldCover (`worldcover`)، آب سطحی JRC (`water`) | Planetary Computer | ندارد |
| Copernicus Data Space، NASA Earthdata، OpenTopography، JAXA | (گام بعد) | **ثبت‌نام یک‌باره**؛ اعتبارنامه از همین حالا در پنل ذخیره می‌شود |

دروازه در `GET /v1/missions` وضعیت هر ماهواره را می‌سنجد (برای هر تأمین‌کننده: جست‌وجوی نمونه روی تهران، **وجود نام باندها در پاسخ کاتالوگ** و خواندن یک فایل کوچک؛ ۱۰ دقیقه کش) و پنل فقط منبع در دسترس را نشان می‌دهد. اگر کاتالوگی نام یک باند را عوض کند، همین بررسی پیش از سفارش کاربر خطای دقیق می‌دهد («داراییِ لازم در کاتالوگ نیست: …»).

## پیکربندی از پنل (نه متغیر محیطی)
هر چیزی که مدیر عوض می‌کند از **تنظیمات سایت ← ماهواره ← منابع ماهواره** است: روشن و خاموش کردن تأمین‌کننده و ماهواره، نشانی کاتالوگ، کلید حساب‌ها، تأمین‌کننده‌ی اولِ هر ماهواره، سقف مساحت و **وزن هر دریافت از سهمیه‌ی مشترک**. پنل پس از ذخیره آن را امضاشده به `PUT /v1/config` می‌فرستد.

- پیکربندی **فقط در حافظه‌ی دروازه** می‌ماند؛ هیچ کلیدی روی دیسک دروازه نیست. با هر راه‌اندازی دوباره، اولین کار پنل ۴۰۹ می‌گیرد و پنل خودکار پیکربندی را می‌فرستد و کار را تکرار می‌کند (کاربر چیزی نمی‌بیند). دکمه‌ی «آزمایش اتصال» هم پیکربندی را می‌فرستد و گزارش می‌دهد.
- هر کار چکیده‌ی پیکربندی پنل (`cfg`) را می‌برد؛ اگر با پیکربندی دروازه نخواند ۴۰۹ با `reason: config` برمی‌گردد. `GET /v1/config` فقط وضعیت را بدون هیچ کلیدی می‌دهد و `GET /v1/health` چکیده را نشان می‌دهد.
- نشانی کاتالوگ فقط `https` و با نام میزبان عمومی پذیرفته می‌شود (نه IP و نه localhost).
- سقف‌های سخت‌افزاری و امنیتی (`SATGATE_MAX_KM2`، `SATGATE_MAX_MB`، `SATGATE_MAX_PIXELS`، `SATGATE_WORKERS`) فقط روی دروازه‌اند؛ پنل فقط می‌تواند **کمتر** بخواهد.
- متغیرهای `SATGATE_STAC_URL` و `SATGATE_LANDSAT_STAC_URL` فقط پیش‌فرض‌اند و نشانی تنظیم‌شده در پنل بر آن‌ها مقدم است. `SATGATE_LANDSAT_TOKEN_URL` دیگر خوانده نمی‌شود.

## فایروال خروجی دروازه
اگر سرور خارجی خروجی را محدود می‌کند، این میزبان‌ها باز باشند (فهرست هر تأمین‌کننده در صفحه‌ی «منابع ماهواره» پنل هم هست):

```
earth-search.aws.element84.com    *.s3.us-west-2.amazonaws.com    *.s3.amazonaws.com
planetarycomputer.microsoft.com   *.blob.core.windows.net
```
برای تأمین‌کننده‌های حساب‌دار (گام بعد) میزبان‌هایشان هم لازم می‌شود: `stac.dataspace.copernicus.eu`، `eodata.dataspace.copernicus.eu`، `identity.dataspace.copernicus.eu`، `cmr.earthdata.nasa.gov`، `urs.earthdata.nasa.gov`، `data.lpdaac.earthdatacloud.nasa.gov`، `hyp3-api.asf.alaska.edu`، `portal.opentopography.org`، `gportal.jaxa.jp`.

## ثبت‌نام حساب‌ها (یک‌باره، رایگان)
| تأمین‌کننده | کجا | در پنل چه بدهید |
|---|---|---|
| Copernicus Data Space | https://dataspace.copernicus.eu ← ثبت‌نام، سپس https://eodata-s3keysmanager.dataspace.copernicus.eu | شناسه‌ی دسترسی S3 و کلید محرمانه‌ی S3 |
| NASA Earthdata | https://urs.earthdata.nasa.gov/users/new (برنامه‌های LP DAAC و ASF را در «Applications» تأیید کنید) | نام کاربری و رمز (یا توکن) |
| OpenTopography | https://portal.opentopography.org/newUser ← «Request API key» | کلید API |
| JAXA G-Portal | https://gportal.jaxa.jp/gpr/ | نام کاربری و رمز |

شرایط استفاده‌ی هر سرویس را پیش از ثبت‌نام بخوانید؛ حساب را اپراتور دروازه (خارج از ایران) می‌سازد. اگر سرویسی ثبت‌نام را نپذیرفت، فقط همان تأمین‌کننده خاموش می‌ماند و بقیه کار می‌کنند.

## تحلیل و پایش
`POST /v1/analyze` چندضلعی‌ها (حداکثر ۱۰۰۰) و یک شاخص (NDVI، NDWI، NDMI، NBR، NDBI) را می‌گیرد (فقط برای ماهواره‌ی چندطیفی، نه رادار و لایه‌ی آماده)، تا ۲۴ تصویر بی‌ابر بازه را روی دروازه می‌خواند و فقط ردیف‌های آمار (میانگین، میانه، کمینه، بیشینه، انحراف معیار، درصد پیکسل معتبر) را به‌صورت JSON برمی‌گرداند (`GET /v1/jobs/<id>/result`). پنل آن را در جدول پایگاه داده‌ی خود کاربر می‌نویسد. پایش خودکار هم همین را هر ۷/۱۴/۳۰ روز برای تصویرهای تازه صدا می‌زند. `GET /v1/health` بار دروازه را هم برمی‌گرداند.

## امنیت و هزینه
- همه‌ی مسیرها جز `/v1/health` امضای `X-Sat-Sig` (HMAC-SHA256 روی زمان، روش، مسیر و چکیده‌ی بدنه) و حداکثر ۲ دقیقه اختلاف ساعت می‌خواهند.
- دروازه فقط به نشانی پنلی که خودش تنظیم شده هوک می‌فرستد، نه هر نشانی که در درخواست بیاید.
- هیچ داده‌ی مشتری روی دروازه نمی‌ماند: فقط محدوده و تصویر برش‌خورده؛ خروجی بعد از تحویل یا حداکثر `SATGATE_KEEP_HOURS` ساعت پاک می‌شود.
- سقف‌ها: `SATGATE_MAX_KM2` (مساحت)، `SATGATE_MAX_MB` (حجم خروجی)، `SATGATE_WORKERS` (برش هم‌زمان)؛ پنل هم سقف پلن کاربر را می‌فرستد و کمینه‌ی دو سقف اعمال می‌شود.
- ترافیک: برش‌ها کوچک‌اند (معمولاً ۱۰ تا ۵۰ مگابایت)، پس هزار درخواست در ماه حدود ۵۰ گیگابایت است.
- اگر `SATGATE_STAC_URL` را عوض کنید می‌شود از کاتالوگ دیگری با همان قرارداد STAC استفاده کرد.

## توسعه
```bash
python -m unittest satgate.tests.test_gateway     # آزمون‌ها با تصویر ساختگی؛ بدون اینترنت
gunicorn satgate.app:application --workers 1 --threads 8
```
فقط **یک** پردازش gunicorn اجرا شود؛ صف کارها در حافظه است (وضعیت و فایل‌ها روی دیسک می‌مانند).
