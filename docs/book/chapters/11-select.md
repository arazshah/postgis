## ساختار یک پرسش

هر پرسش `SELECT` از چند **بند** (clause) ساخته می‌شود که ترتیب نوشتن‌شان ثابت است:

```sql
SELECT   ستون‌ها و محاسبه‌ها       -- چه چیزی برگردد
FROM     جدول                      -- از کجا
WHERE    شرط روی سطرها             -- کدام سطرها
GROUP BY دسته‌بندی                  -- (فصل ۱۲)
HAVING   شرط روی دسته‌ها            -- (فصل ۱۲)
ORDER BY مرتب‌سازی                  -- به چه ترتیبی
LIMIT    تعداد                     -- چند سطر
OFFSET   پرش                       -- از سطر چندم
```

اما پایگاه داده آن‌ها را به ترتیب دیگری **اجرا** می‌کند و دانستن این ترتیب بسیاری از خطاها را توضیح می‌دهد:

`FROM` ← `WHERE` ← `GROUP BY` ← `HAVING` ← `SELECT` ← `ORDER BY` ← `LIMIT`

یعنی اول جدول خوانده می‌شود، سطرها فیلتر می‌شوند، دسته‌بندی می‌شوند، ستون‌های خروجی ساخته می‌شوند و در آخر مرتب و محدود می‌شوند.
به همین دلیل نمی‌توانید در `WHERE` از نام مستعاری که در `SELECT` ساخته‌اید استفاده کنید (هنوز ساخته نشده)، ولی در `ORDER BY`
می‌توانید.

## انتخاب ستون‌ها

به جای `*` بهتر است فقط ستون‌هایی را بخواهید که لازم دارید؛ پرسش خواناتر و سریع‌تر می‌شود:

```{.sql .run rows=4}
SELECT name, level, students
FROM schools
LIMIT 4;
```

### نام مستعار و محاسبه

با `AS` به ستون نام تازه می‌دهید و می‌توانید هر محاسبه‌ای را ستون کنید:

```{.sql .run rows=4}
SELECT name                       AS school_name,
       students,
       round(students / 30.0)     AS classes_needed,
       students >= 500            AS is_large
FROM schools
LIMIT 4;
```

::: note
**نام مستعار فارسی؟** می‌توانید نام ستون را فارسی بگذارید، به شرطی که داخل گیومه‌ی دوتایی باشد: `AS "تعداد کلاس"`. اما نام‌های
فارسی در کد و نرم‌افزارهای دیگر دردسر درست می‌کنند؛ پیشنهاد این کتاب نام انگلیسی برای ستون و فارسی برای *برچسب* روی نقشه و نمودار است.
:::

### DISTINCT: مقدارهای یکتا

```{.sql .run}
SELECT DISTINCT line FROM metro_stations ORDER BY line;
```

## فیلتر کردن با WHERE

`WHERE` شرطی می‌گیرد که برای هر سطر درست یا نادرست است؛ فقط سطرهایی که شرط برایشان **درست** است باقی می‌مانند.

### عملگرهای مقایسه

| عملگر | معنا |
|---|---|
| `=` | برابر |
| `<>` یا `!=` | نابرابر |
| `<` `<=` `>` `>=` | کوچک‌تر، بزرگ‌تر |
| `BETWEEN a AND b` | بین a و b (شامل خود a و b) |
| `IN (…)` | یکی از این مقدارها |
| `IS NULL` / `IS NOT NULL` | خالی / غیرخالی |
| `LIKE` / `ILIKE` | تطابق الگوی متنی (ILIKE بدون حساسیت به بزرگی حروف) |

```{.sql .run rows=5}
SELECT name, level, students
FROM schools
WHERE students > 850
ORDER BY students DESC;
```

متن داخل **گیومه‌ی تکی** نوشته می‌شود. گیومه‌ی دوتایی برای *نام* ستون و جدول است، نه مقدار:

```{.sql .run}
SELECT count(*) AS primary_schools
FROM schools
WHERE level = 'ابتدایی';
```

### ترکیب شرط‌ها

`AND` (هر دو)، `OR` (دست‌کم یکی) و `NOT` (نقیض). `AND` از `OR` اولویت بیشتری دارد؛ همیشه با پرانتز منظورتان را روشن کنید:

```{.sql .run rows=4}
SELECT name, level, students
FROM schools
WHERE (level = 'ابتدایی' OR level = 'متوسطه اول')
  AND students BETWEEN 400 AND 450
ORDER BY students;
```

همان شرط با `IN` کوتاه‌تر است:

```{.sql .run rows=4}
SELECT name, level, students
FROM schools
WHERE level IN ('ابتدایی', 'متوسطه اول')
  AND students BETWEEN 400 AND 450
ORDER BY students;
```

::: warn
**دام پرانتز.** پرسش `WHERE level = 'ابتدایی' OR level = 'متوسطه اول' AND students > 800` یعنی «همه‌ی مدرسه‌های ابتدایی، به‌علاوه‌ی
مدرسه‌های متوسطه‌ی اول بالای ۸۰۰ دانش‌آموز»، چون `AND` اول اجرا می‌شود. احتمالاً منظورتان این نبوده است.
:::

### الگوی متنی با LIKE

در `LIKE`، علامت `%` یعنی «هر تعداد نویسه» و `_` یعنی «دقیقاً یک نویسه»:

```{.sql .run rows=4}
SELECT name FROM schools WHERE name LIKE '%12%' ORDER BY name;
```

## مرتب‌سازی، محدود کردن و صفحه‌بندی

`ORDER BY` با `ASC` (صعودی، پیش‌فرض) و `DESC` (نزولی). چند ستون را می‌توان پشت هم آورد: اول بر اساس اولی، و در سطرهای برابر
بر اساس دومی.

```{.sql .run rows=6}
SELECT level, name, students
FROM schools
ORDER BY level, students DESC
LIMIT 6;
```

`LIMIT n OFFSET m` یعنی «از سطر m+1، n سطر بده»؛ این همان صفحه‌بندی ۵۰ سطری مرورگر داده است (صفحه‌ی سوم: `LIMIT 50 OFFSET 100`).

::: pro
**صفحه‌بندی بدون OFFSET.** `OFFSET` بزرگ کند است، چون پایگاه باید همه‌ی سطرهای قبلی را بخواند و دور بریزد. برای جدول‌های بزرگ،
صفحه‌بندی **کلیدی** (keyset) سریع‌تر است: به جای `OFFSET 100000` بنویسید `WHERE gid > آخرین_gid_صفحه‌ی_قبل ORDER BY gid LIMIT 50`.
:::

`NULL`ها در مرتب‌سازی صعودی آخر می‌آیند؛ با `NULLS FIRST` یا `NULLS LAST` آن را کنترل کنید.

## دسته‌بندی با CASE

`CASE` شرط «اگر … آنگاه …» SQL است و برای ساختن دسته از مقدار عددی (طبقه‌بندی) کاربرد زیادی دارد؛ همان کاری که در نقشه‌ی
موضوعی انجام می‌دهیم:

```{.sql .run rows=6}
SELECT name, students,
       CASE
         WHEN students < 300 THEN 'کوچک'
         WHEN students < 700 THEN 'متوسط'
         ELSE 'بزرگ'
       END AS size_class
FROM schools
ORDER BY gid
LIMIT 6;
```

شرط‌ها به ترتیب بررسی می‌شوند و اولین شرط درست برنده است؛ پس ترتیب `WHEN`ها مهم است.

## توابع پرکاربرد

### متنی

```{.sql .run}
SELECT length('مدرسه ۱۲')                    AS len,
       replace('مدرسه 12', 'مدرسه', 'دبستان') AS replaced,
       split_part('خط ۳', ' ', 2)            AS line_no,
       'خط' || ' ' || '۴'                    AS concat_op,
       trim('  فاصله  ')                     AS trimmed,
       translate('۱۲۳', '۰۱۲۳۴۵۶۷۸۹', '0123456789')::int + 1 AS persian_digits;
```

آخرین ستون یک ترفند کاربردی برای داده‌ی ایرانی است: رقم‌های فارسی را با `translate` به لاتین تبدیل می‌کند تا بتوان آن را عدد کرد.
در داده‌ی واقعی گاهی هر دو نوع رقم (و حتی رقم عربی ٤٥٦) را با هم می‌بینید؛ یکدست کردن آن‌ها پیش از تحلیل لازم است.

::: warn
**«ی» و «ک» عربی.** متن فارسی که از منابع مختلف می‌آید ممکن است «ي» و «ك» عربی داشته باشد. «علي» و «علی» برای پایگاه داده دو
متن متفاوت‌اند و جست‌وجوی یکی دیگری را پیدا نمی‌کند. پیش از تحلیل یکدست کنید:
`UPDATE t SET name = translate(name, 'يك', 'یک');`
:::

### عددی

`round(x, n)`، `ceil(x)`، `floor(x)`، `abs(x)`، `power(x, y)`، `sqrt(x)`، `greatest(a, b, …)`، `least(a, b, …)` و `random()`.

### تاریخ و زمان

```{.sql .run}
SELECT current_date                                AS today,
       current_date - date '2025-03-21'            AS days_since_nowruz_1404,
       extract(year FROM current_date)             AS year,
       date_trunc('month', now())::date            AS month_start,
       (current_date + interval '30 days')::date   AS in_30_days;
```

تفاضل دو تاریخ، تعداد روز است. `interval` بازه‌ی زمانی است و `extract` و `date_trunc` بخشی از تاریخ را جدا یا تاریخ را به آغاز
ماه و سال گرد می‌کنند؛ پایه‌ی همه‌ی گزارش‌های زمانی و سری‌های زمانی ماهواره‌ای در فصل ۳۷.

## جست‌وجوی تقریبی نام‌ها

کاربر می‌نویسد «درمانگا» و انتظار دارد «درمانگاه» را پیدا کند. افزونه‌ی `pg_trgm` (که در فصل ۵ نصب کردیم) شباهت دو متن را بر
اساس **سه‌نویسه‌ای**‌های مشترکشان می‌سنجد:

```{.sql .run rows=4}
SELECT name, type, similarity(type, 'درمانگا') AS sim
FROM health_centers
WHERE type % 'درمانگا'
ORDER BY sim DESC, name
LIMIT 4;
```

عملگر `%` یعنی «به اندازه‌ی کافی شبیه» (پیش‌فرض شباهت ۰٫۳). با یک شاخص از نوع GIN روی ستون، این جست‌وجو روی میلیون‌ها نام هم سریع
است: `CREATE INDEX ON health_centers USING gin (name gin_trgm_ops);` این روش پایه‌ی ساختن جست‌وجوی نشانی و نام مکان است.

::: try
پرسشی بنویسید که مراکز درمانی با بیش از ۵۰ تخت را، از نوع بیمارستان یا درمانگاه، به ترتیب تعداد تخت (نزولی) برگرداند و برای هر
کدام ستون «ظرفیت» با مقدار «زیاد» (۷۰ تخت و بیشتر) یا «متوسط» بسازد.
:::

::: summary
- ترتیب نوشتن: SELECT، FROM، WHERE، GROUP BY، HAVING، ORDER BY، LIMIT؛ ترتیب اجرا: FROM، WHERE، GROUP BY، HAVING، SELECT، ORDER BY، LIMIT.
- مقدار متنی در گیومه‌ی تکی؛ نام ستون در گیومه‌ی دوتایی.
- `AND` پیش از `OR` اجرا می‌شود؛ پرانتز بگذارید. `IN` و `BETWEEN` شرط‌ها را کوتاه می‌کنند.
- `CASE` برای دسته‌بندی؛ اولین شرط درست برنده است.
- توابع متنی، عددی و تاریخی؛ رقم فارسی و «ی/ک» عربی را پیش از تحلیل یکدست کنید.
- `pg_trgm` جست‌وجوی تقریبی نام را ممکن می‌کند.
:::

::: teach
**زمان پیشنهادی:** دو جلسه. هر مفهوم را با یک «پرسش از مدیر» شروع کنید: «مدرسه‌های بزرگ کدام‌اند؟» و بگذارید دانشجوها آن را به
SQL ترجمه کنند. ترتیب اجرای بندها را روی تخته بکشید و خطای استفاده از نام مستعار در WHERE را عمداً نشان دهید.
:::
