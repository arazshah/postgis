## از پیکسل تا کلاس

**طبقه‌بندی تصویر** هر پیکسل را به یک **کلاس** پوشش زمین نسبت می‌دهد: آب، جنگل، مزرعه، مرتع، شهر، خاک لخت. نتیجه یک رستر گسسته (فصل ۲) است که پایه‌ی نقشه‌های
کاربری اراضی، برآورد سطح زیر کشت و مطالعه‌ی تغییرات است. ایده‌ی اصلی همان امضای طیفی فصل ۳۱ است: پیکسل‌هایی که امضای مشابه دارند، احتمالاً یک نوع
پوشش‌اند.

::: note
**جایگاه در پایگاه داده مکانی ابری.** سامانه طبقه‌بندی‌کننده‌ی آماده ندارد. جریان کار پیشنهادی این است: تصویر «همه‌ی باندها» را از سامانه بگیرید (فصل ۳۴)،
نمونه‌های آموزشی را در یک جدول پایگاه داده نگه دارید، طبقه‌بندی را در QGIS انجام دهید و نتیجه را به پایگاه برگردانید تا ارزیابی صحت، آمار مساحت و
مقایسه‌ی تغییر با SQL و ابزارهای سامانه انجام شود.
:::

## سه رویکرد

| رویکرد | چگونه | مزیت | محدودیت |
|---|---|---|---|
| **نظارت‌نشده** (unsupervised) | الگوریتم پیکسل‌ها را بر اساس شباهت طیفی گروه‌بندی می‌کند (k-means، ISODATA)؛ کارشناس بعداً به هر گروه نام می‌دهد | سریع، بدون نمونه | گروه‌ها لزوماً با کلاس‌های مورد نظر یکی نیستند |
| **نظارت‌شده** (supervised) | کارشناس برای هر کلاس نمونه‌ی آموزشی معرفی می‌کند؛ الگوریتم از آن‌ها یاد می‌گیرد | کنترل کلاس‌ها، دقت بیشتر | نیاز به نمونه‌ی خوب و کافی |
| **شیءگرا** (OBIA) | تصویر ابتدا به **قطعه‌ها**ی همگن بخش‌بندی، سپس هر قطعه با ویژگی‌های طیفی، شکل و بافت طبقه‌بندی می‌شود | نتیجه‌ی تمیز، مناسب تصویر با تفکیک بالا | پیچیده‌تر، حساس به تنظیم بخش‌بندی |

### طبقه‌بندی‌کننده‌های رایج

- **بیشینه‌ی احتمال** (Maximum Likelihood): فرض می‌کند پیکسل‌های هر کلاس توزیع نرمال دارند؛ کلاسیک و سریع.
- **جنگل تصادفی** (Random Forest): صدها درخت تصمیم که هر کدام روی بخشی از نمونه‌ها و باندها آموزش می‌بینند و رأی می‌دهند؛ امروز پرکاربردترین انتخاب، مقاوم
  و بدون فرض توزیع.
- **ماشین بردار پشتیبان** (SVM): مرز بهینه بین کلاس‌ها؛ با نمونه‌ی کم هم خوب است.
- **یادگیری عمیق** (شبکه‌های کانولوشنی): برای تصویرهای با تفکیک بالا و الگوهای مکانی پیچیده؛ نیاز به نمونه‌ی بسیار زیاد.

## نمونه‌ی آموزشی در پایگاه داده

کیفیت طبقه‌بندی نظارت‌شده بیش از هر چیز به **نمونه‌ی آموزشی** بستگی دارد. نگه داشتن نمونه‌ها در پایگاه داده (به جای فایل‌های پراکنده) آن‌ها را چندکاربره،
تکرارپذیر و قابل بازبینی می‌کند:

```{.sql .run}
CREATE TABLE lc_classes (id smallint PRIMARY KEY, name text NOT NULL UNIQUE, color text);
INSERT INTO lc_classes VALUES (1, 'آب', '#3a86c9'), (2, 'جنگل و باغ', '#2e7d4f'), (3, 'زراعت', '#8bb04a'),
                              (4, 'مرتع', '#c9b46a'), (5, 'شهر', '#b23a35'), (6, 'خاک لخت', '#a67c3d');

CREATE TABLE training_samples (
  gid        serial PRIMARY KEY,
  class_id   smallint NOT NULL REFERENCES lc_classes(id),
  purpose    text NOT NULL CHECK (purpose IN ('train', 'validate')),   -- جدا کردن نمونه‌ی آموزش از ارزیابی
  collector  text,
  checked_on date DEFAULT current_date,
  geom       geometry(Polygon, 4326) NOT NULL CHECK (ST_IsValid(geom))
);
CREATE INDEX ON training_samples USING gist (geom);

SELECT id, name FROM lc_classes ORDER BY id;
```

قاعده‌های نمونه‌ی خوب:

- **نماینده** باشد: از همه‌جای منطقه و همه‌ی گونه‌های هر کلاس (مزرعه‌ی سبز و تازه‌برداشت‌شده هر دو «زراعت»‌اند).
- **همگن** باشد: چندضلعی آموزشی فقط یک کلاس داشته باشد و از لبه‌ها فاصله بگیرد (پیکسل مختلط، فصل ۳۲).
- **کافی** باشد: قاعده‌ی سرانگشتی دست‌کم ده تا صد برابر تعداد باندها پیکسل برای هر کلاس.
- **جدا** باشد: بخشی از نمونه‌ها (معمولاً ۳۰ درصد) را برای **ارزیابی صحت** کنار بگذارید و در آموزش استفاده نکنید (ستون `purpose`).
- با **بازدید میدانی** یا تصویر با تفکیک بالاتر تأیید شده باشد. برداشت میدانی سامانه (فصل ۴۸) برای جمع‌آوری نمونه با گوشی مناسب است.

## جریان کار در QGIS

::: steps
1. تصویر «همه‌ی باندها»ی Sentinel-2 را از سامانه بگیرید (برای کشاورزی، تاریخ اوج رشد؛ یا ترکیب بی‌ابر فصلی) و در QGIS باز کنید.
2. لایه‌ی `training_samples` را از پایگاه داده باز کنید (فصل ۶) و چندضلعی‌های نمونه را رقومی کنید؛ هر کارشناس می‌تواند هم‌زمان کار کند.
3. باندهای کمکی بسازید: NDVI، NDWI و NDBI (فصل ۳۵) اغلب تفکیک کلاس‌ها را بهتر می‌کنند و می‌توان آن‌ها را به‌عنوان باند اضافه به طبقه‌بندی داد.
4. طبقه‌بندی: با پلاگین **Semi-Automatic Classification (SCP)** یا ابزارهای **Orfeo Toolbox** و **dzetsaka**، جنگل تصادفی را روی نمونه‌های `purpose = 'train'` آموزش و
   روی تصویر اجرا کنید.
5. پس‌پردازش: فیلتر اکثریت (Sieve یا Majority) پیکسل‌های تک‌افتاده را حذف می‌کند.
6. برداری کنید (Polygonize) و نتیجه را با DB Manager به جدول `landcover_1405` در پایگاه وارد کنید؛ یا رستر را با raster2pgsql (فصل ۲۳).
:::

پس از ورود، مساحت هر کلاس با یک پرسش ساده به دست می‌آید:
`SELECT class_id, sum(ST_Area(geom::geography)) / 10000 AS ha FROM landcover_1405 GROUP BY class_id;`

## ارزیابی صحت

نقشه‌ای که صحتش سنجیده نشده، نقشه نیست؛ حدس است. **ماتریس خطا** (confusion matrix) برای نمونه‌های ارزیابی، کلاس واقعی (مرجع) را با کلاس پیش‌بینی‌شده
مقایسه می‌کند. فرض کنید پس از پیوند مکانی نمونه‌های `validate` با نقشه‌ی طبقه‌بندی، این شمارش را داریم:

```{.sql .run}
WITH m(reference, predicted, n) AS (VALUES
  ('آب','آب',48), ('آب','زراعت',1), ('آب','شهر',1),
  ('زراعت','زراعت',87), ('زراعت','مرتع',9), ('زراعت','آب',2),
  ('مرتع','مرتع',61), ('مرتع','زراعت',12), ('مرتع','خاک لخت',7),
  ('شهر','شهر',55), ('شهر','خاک لخت',6),
  ('خاک لخت','خاک لخت',38), ('خاک لخت','شهر',8), ('خاک لخت','مرتع',5))
SELECT reference,
       coalesce(sum(n) FILTER (WHERE predicted = 'آب'), 0)      AS "آب",
       coalesce(sum(n) FILTER (WHERE predicted = 'زراعت'), 0)   AS "زراعت",
       coalesce(sum(n) FILTER (WHERE predicted = 'مرتع'), 0)    AS "مرتع",
       coalesce(sum(n) FILTER (WHERE predicted = 'شهر'), 0)     AS "شهر",
       coalesce(sum(n) FILTER (WHERE predicted = 'خاک لخت'), 0) AS "خاک لخت",
       sum(n) AS total
FROM m GROUP BY reference ORDER BY reference;
```

سطرها کلاس واقعی و ستون‌ها کلاس پیش‌بینی‌شده‌اند (`coalesce` خانه‌های خالی را صفر می‌کند). قطر اصلی، پیکسل‌های درست‌طبقه‌بندی‌شده است. از این ماتریس چند معیار استاندارد به دست می‌آید:

- **صحت کلی** (overall accuracy): مجموع قطر ÷ کل.
- **صحت تولیدکننده** (producer's accuracy) برای هر کلاس: درست‌ها ÷ مجموع سطر. «از کل جنگل‌های واقعی، چند درصد را جنگل نقشه کردیم؟» (مکمل آن **خطای حذف** است.)
- **صحت کاربر** (user's accuracy): درست‌ها ÷ مجموع ستون. «اگر روی نقشه جایی جنگل است، چقدر احتمال دارد واقعاً جنگل باشد؟» (مکمل آن **خطای اضافه** است.)
- **ضریب کاپا** (κ، کوهن): توافق فراتر از شانس؛ $\kappa = (p_o - p_e)/(1 - p_e)$ که $p_o$ صحت کلی و $p_e$ توافق مورد انتظار تصادفی است.

```{.sql .run}
WITH m(reference, predicted, n) AS (VALUES
  ('آب','آب',48), ('آب','زراعت',1), ('آب','شهر',1),
  ('زراعت','زراعت',87), ('زراعت','مرتع',9), ('زراعت','آب',2),
  ('مرتع','مرتع',61), ('مرتع','زراعت',12), ('مرتع','خاک لخت',7),
  ('شهر','شهر',55), ('شهر','خاک لخت',6),
  ('خاک لخت','خاک لخت',38), ('خاک لخت','شهر',8), ('خاک لخت','مرتع',5)),
tot AS (SELECT sum(n)::numeric AS t FROM m),
cls AS (SELECT DISTINCT reference AS c FROM m),
per AS (
  SELECT c,
         (SELECT coalesce(sum(n), 0) FROM m WHERE reference = c AND predicted = c) AS correct,
         (SELECT sum(n) FROM m WHERE reference = c)  AS row_total,
         (SELECT coalesce(sum(n), 0) FROM m WHERE predicted = c) AS col_total
  FROM cls
)
SELECT c AS class,
       round(100.0 * correct / row_total, 1) AS producer_pct,
       round(100.0 * correct / col_total, 1) AS user_pct,
       round(100 * (SELECT sum(correct) FROM per) / t, 1) AS overall_pct,
       round(((SELECT sum(correct) FROM per) / t - (SELECT sum(row_total * col_total) FROM per) / t ^ 2)
             / (1 - (SELECT sum(row_total * col_total) FROM per) / t ^ 2), 3) AS kappa
FROM per, tot
ORDER BY producer_pct;
```

صحت کلی حدود ۸۵ درصد و کاپا حدود ۰٫۸ است که برای نقشه‌ی پوشش زمین با Sentinel-2 قابل قبول به شمار می‌رود. اما نگاه به کلاس‌ها مهم‌تر است: مرتع با زراعت و خاک
لخت با شهر بیشترین اشتباه را دارند؛ دو جفت کلاسی که امضای طیفی مشابهی دارند. راه بهبود: نمونه‌ی بیشتر برای این کلاس‌ها، افزودن شاخص‌ها و تصویر چندزمانه
(مرتع و زراعت در زمان‌های مختلف سال رفتار متفاوتی دارند).

## آشکارسازی تغییر

«چه چیزی بین دو تاریخ عوض شده؟» دو رویکرد اصلی دارد:

**۱. تفاضل تصویر یا شاخص.** شاخص دو تاریخ کم می‌شود و پیکسل‌هایی با تفاضل بیش از آستانه «تغییر» به حساب می‌آیند: dNBR برای آتش (فصل ۳۵)، تفاضل NDVI برای
تخریب پوشش گیاهی، تفاضل NDWI برای تغییر آب. ساده و سریع است، اما **نوع** تغییر را نمی‌گوید و به تفاوت فصل و جو حساس است؛ دو تاریخ را از یک فصل انتخاب کنید.
در سامانه، سری زمانی «آمار هر قطعه» همین را در سطح قطعه انجام می‌دهد (فصل ۳۷).

**۲. مقایسه‌ی پس از طبقه‌بندی.** هر تاریخ جداگانه طبقه‌بندی و دو نقشه روی هم گذاشته می‌شوند. نتیجه یک **ماتریس تغییر** «از ← به» است: چند هکتار زراعت به شهر
تبدیل شده؟ نوع تغییر معلوم است، اما خطای هر دو طبقه‌بندی در نتیجه جمع می‌شود. برای نقشه‌های برداری، ابزار **«تغییر بین دو نسخه»** سامانه (فصل ۲۷) دقیقاً
همین ماتریس را می‌سازد و با نمودار **Sankey** در استودیوی نقشه نمایش می‌دهد (فصل ۴۳). معادل SQL آن، اشتراک دو لایه و گروه‌بندی بر اساس هر دو کلاس است:

```sql
SELECT a.class_id AS from_class, b.class_id AS to_class,
       round(sum(ST_Area(ST_Intersection(a.geom, b.geom)::geography)) / 10000) AS hectares
FROM landcover_1400 a
JOIN landcover_1405 b ON ST_Intersects(a.geom, b.geom)
GROUP BY 1, 2
ORDER BY hectares DESC;
```

::: real
**گسترش شهر در حریم رودخانه.** با دو نقشه‌ی پوشش زمین ۱۳۹۵ و ۱۴۰۵ (هر دو از Landsat و Sentinel-2 با جنگل تصادفی) و حریم ۱۵۰ متری رودخانه‌ها (فصل ۱۸)، ماتریس
تغییر داخل حریم نشان داد ۲۱۰ هکتار باغ و زراعت در ده سال به «شهر» تبدیل شده است. نقشه‌ی همین چندضلعی‌ها، که در استودیوی نقشه منتشر شد، مبنای بازدید
مأموران حفاظت رودخانه قرار گرفت.
:::

::: summary
- طبقه‌بندی هر پیکسل را به کلاس پوشش زمین نسبت می‌دهد: نظارت‌نشده (k-means)، نظارت‌شده (جنگل تصادفی، SVM، بیشینه‌ی احتمال) یا شیءگرا.
- نمونه‌ی آموزشی را در جدول پایگاه داده با کلید خارجی کلاس و ستون آموزش/ارزیابی نگه دارید؛ نماینده، همگن، کافی و جدا.
- جریان کار: «همه‌ی باندها» ← QGIS (SCP، OTB) ← پس‌پردازش ← برگرداندن به پایگاه.
- ارزیابی: ماتریس خطا، صحت کلی، صحت تولیدکننده و کاربر، کاپا؛ همه با SQL.
- تغییر: تفاضل شاخص (سریع، بی‌نوع) یا مقایسه‌ی پس از طبقه‌بندی (ماتریس «از ← به»؛ ابزار «تغییر بین دو نسخه» و Sankey).
:::

::: teach
**زمان پیشنهادی:** سه جلسه (یک جلسه نظری، یک جلسه نمونه‌گیری گروهی در جدول مشترک، یک جلسه طبقه‌بندی و ارزیابی). نمونه‌گیری گروهی در یک جدول مشترک
پایگاه داده، تجربه‌ی کار تیمی واقعی است و مسئله‌ی «نمونه‌ی بد یک نفر کل نقشه را خراب می‌کند» را ملموس می‌کند.
:::
