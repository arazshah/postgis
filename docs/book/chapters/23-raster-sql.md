## رستر کنار برداری

در فصل ۲ دیدیم که رستر شبکه‌ای از پیکسل‌هاست. افزونه‌ی `postgis_raster` نوع داده‌ی `raster` را اضافه می‌کند تا رستر هم مثل هندسه در جدول
بنشیند و با SQL پرسیده شود؛ از همه مهم‌تر، **کنار داده‌ی برداری**: «میانگین ارتفاع هر قطعه»، «شیب محل هر چاه»، «درصد پوشش گیاهی هر محله».

| مفهوم | در PostGIS |
|---|---|
| کاشی | رستر بزرگ معمولاً به **کاشی**‌های کوچک (مثلاً ۲۵۶×۲۵۶) شکسته و هر کاشی یک سطر جدول می‌شود |
| باند | هر کاشی یک یا چند باند دارد؛ `ST_NumBands(rast)` |
| نوع پیکسل | `8BUI` (صحیح بی‌علامت ۸ بیتی)، `16BSI`، `32BF` (اعشاری ۳۲ بیتی)، … |
| بی‌داده | مقدار NoData هر باند؛ `ST_BandNoDataValue(rast, 1)` |
| مرجع مکانی | گوشه‌ی بالا-چپ، اندازه‌ی پیکسل، چرخش و SRID؛ `ST_MetaData(rast)` |

::: note
**در پایگاه داده مکانی ابری، رستر کجاست؟** تصویرهای ماهواره‌ای و DEM که بخش «تصویر ماهواره‌ای» تهیه می‌کند (بخش ششم کتاب) به صورت **فایل
COG** نگه داشته می‌شوند، نه داخل پایگاه داده؛ و «آمار هر قطعه» آن‌ها را بدون نیاز به این افزونه محاسبه می‌کند. افزونه‌ی رستر وقتی لازم است
که بخواهید رستر خودتان را داخل پایگاه بیاورید و با SQL تحلیل کنید. یادتان باشد رستر حجم زیادی از سهمیه را می‌گیرد؛ پیش از ورود، آن را به
محدوده‌ی مطالعه برش دهید.
:::

## ورود رستر

ابزار `raster2pgsql` (همراه PostGIS) فایل رستر را به دستورهای SQL تبدیل می‌کند:

```bash
raster2pgsql -s 32639 -I -C -M -t 256x256 -N -9999 dem.tif public.dem | psql "host=… sslmode=require"
```

| گزینه | معنا |
|---|---|
| `-s 32639` | SRID رستر |
| `-I` | ساخت شاخص مکانی روی محدوده‌ی کاشی‌ها |
| `-C` | افزودن قیدهای رستر (همه‌ی کاشی‌ها هم‌SRID، هم‌اندازه‌ی پیکسل) |
| `-M` | اجرای VACUUM ANALYZE پس از ورود |
| `-t 256x256` | اندازه‌ی کاشی؛ کاشی کوچک برای پرسش‌های محلی سریع‌تر است |
| `-N -9999` | مقدار بی‌داده |
| `-R` | رستر **بیرون از پایگاه** (out-db): فقط مسیر فایل ذخیره می‌شود |

برای این فصل، یک مدل ارتفاعی ساختگی (دو تپه روی یک دامنه‌ی ملایم) در غرب تهران با پیکسل ۳۰ متری می‌سازیم تا بدون فایل خارجی کار کنیم. دستور
زیر را یک بار در کنسول با «اجازه تغییر داده» اجرا کنید؛ کدهای بعدی این فصل روی همین جدول اجرا شده‌اند:

```{.sql .run}
CREATE TABLE dem AS
SELECT 1 AS rid,
       ST_MapAlgebra(
         ST_AddBand(ST_MakeEmptyRaster(200, 200, 530000, 3955000, 30, -30, 0, 0, 32639), '32BF'::text, 0, -9999),
         1, '32BF',
         '1200 + 400 * exp(-((([rast.x] - 70)^2 + ([rast.y] - 90)^2) / 1800.0))
               + 150 * exp(-((([rast.x] - 150)^2 + ([rast.y] - 140)^2) / 900.0)) + 0.8 * [rast.y]'
       ) AS rast;

SELECT (ST_MetaData(rast)).* FROM dem;
```

`ST_MakeEmptyRaster(ستون، سطر، x گوشه، y گوشه، اندازه‌ی پیکسل x، اندازه‌ی پیکسل y، چرخش، چرخش، SRID)` یک رستر خالی ۲۰۰×۲۰۰ می‌سازد. اندازه‌ی
پیکسل y منفی است چون سطرها از بالا به پایین شماره می‌خورند. `ST_MapAlgebra` مقدار هر پیکسل را از یک عبارت حساب می‌کند؛ `[rast.x]` و `[rast.y]`
شماره‌ی ستون و سطر پیکسل‌اند.

## آمار و مقدار پیکسل

```{.sql .run setup=dem}
SELECT (stats).count, round((stats).mean::numeric, 1) AS mean_m,
       round((stats).min::numeric, 1) AS min_m, round((stats).max::numeric, 1) AS max_m,
       round((stats).stddev::numeric, 1) AS std_m
FROM (SELECT ST_SummaryStats(rast) AS stats FROM dem) s;
```

**مقدار در نقطه:** «ارتفاع محل هر مدرسه» با `ST_Value`. نقطه باید در SRID رستر باشد؛ پس آن را تبدیل می‌کنیم (نه رستر را؛ همان قاعده‌ی فصل ۲۰):

```{.sql .run setup=dem rows=5}
SELECT s.name, round(ST_Value(d.rast, ST_Transform(s.geom, 32639))::numeric, 1) AS elevation_m
FROM schools s
JOIN dem d ON ST_Intersects(d.rast, ST_Transform(s.geom, 32639))
ORDER BY elevation_m DESC
LIMIT 5;
```

`ST_Intersects(rast, geom)` فقط مدرسه‌هایی را نگه می‌دارد که روی رستر افتاده‌اند (و با شاخص روی کاشی‌ها سریع است). اگر جدول ستون ارتفاع
داشته باشد، با `UPDATE … SET elev = ST_Value(…)` پر می‌شود؛ یا نقطه را سه‌بعدی می‌کنید: `ST_MakePoint(ST_X(g), ST_Y(g), ST_Value(…))` (فصل ۲۲).

## آمار ناحیه‌ای

**آمار ناحیه‌ای** (zonal statistics) آمار پیکسل‌های داخل هر چندضلعی است و پرکاربردترین تلفیق رستر و برداری: میانگین ارتفاع هر قطعه، میانگین
NDVI هر مزرعه، بیشینه‌ی دمای هر محله. `ST_Clip` رستر را با چندضلعی می‌بُرد و `ST_SummaryStats` آمار را می‌گیرد:

```{.sql .run setup=dem}
SELECT n.name,
       (s).count                       AS pixels,
       round((s).mean::numeric, 1)     AS mean_elev_m,
       round((s).max::numeric, 1)      AS max_elev_m
FROM (
  SELECT n.name, ST_SummaryStats(ST_Clip(d.rast, ST_Transform(n.geom, 32639))) AS s
  FROM neighborhoods n
  JOIN dem d ON ST_Intersects(d.rast, ST_Transform(n.geom, 32639))
) n
ORDER BY mean_elev_m DESC;
```

فقط محله‌هایی آمدند که با محدوده‌ی DEM برخورد دارند. برای رستری که چند کاشی دارد، آمار هر کاشی جدا حساب می‌شود و باید با `ST_Union` کاشی‌ها
را پیش از برش یکی کنید یا آمار را با وزن تعداد پیکسل تجمیع کنید. «آمار هر قطعه» در بخش تصویر ماهواره‌ای (فصل ۳۶) همین تحلیل را روی NDVI
و برای سری زمانی انجام می‌دهد.

## تحلیل ارتفاع: شیب، جهت و سایه‌روشن

از مدل رقومی ارتفاع (DEM) سه رستر مشتق پرکاربرد ساخته می‌شود:

- **شیب** (slope): تندی دامنه به درجه یا درصد؛ برای مکان‌یابی ساخت‌وساز، فرسایش و کشاورزی.
- **جهت** (aspect): سمتی که دامنه رو به آن است (۰ تا ۳۶۰، شمال = ۰)؛ برای تابش خورشید، کشاورزی و انرژی خورشیدی.
- **سایه‌روشن** (hillshade): تصویری که برجستگی را با نور فرضی از یک جهت نشان می‌دهد؛ زمینه‌ی نقشه‌های توپوگرافی.

```{.sql .run setup=dem}
WITH d AS (SELECT rast FROM dem)
SELECT 'شیب (درجه)' AS layer, round((ST_SummaryStats(ST_Slope(rast, 1, '32BF', 'DEGREES'))).mean::numeric, 2) AS mean,
       round((ST_SummaryStats(ST_Slope(rast, 1, '32BF', 'DEGREES'))).max::numeric, 2) AS max FROM d
UNION ALL
SELECT 'جهت (درجه)', round((ST_SummaryStats(ST_Aspect(rast, 1, '32BF', 'DEGREES'))).mean::numeric, 1),
       round((ST_SummaryStats(ST_Aspect(rast, 1, '32BF', 'DEGREES'))).max::numeric, 1) FROM d
UNION ALL
SELECT 'سایه‌روشن (۰ تا ۲۵۵)', round((ST_SummaryStats(ST_HillShade(rast, 1, '32BF', 315, 45))).mean::numeric, 1),
       round((ST_SummaryStats(ST_HillShade(rast, 1, '32BF', 315, 45))).max::numeric, 1) FROM d;
```

`ST_HillShade(rast, باند، نوع، آزیموت نور، ارتفاع نور)` با نور از شمال‌غرب (۳۱۵ درجه) و زاویه‌ی ۴۵ درجه، قرارداد رایج کارتوگرافی است.

::: know
**شیب چگونه حساب می‌شود؟** برای هر پیکسل، از ارتفاع هشت همسایه‌اش، تغییر ارتفاع در جهت x و y ($\partial z/\partial x$ و $\partial z/\partial y$)
با روش هورن تخمین زده می‌شود و شیب برابر است با $\arctan\sqrt{(\partial z/\partial x)^2 + (\partial z/\partial y)^2}$. برای همین DEM باید در
سیستمی متری (مثل UTM) باشد: اگر اندازه‌ی پیکسل به درجه و ارتفاع به متر باشد، شیب بی‌معنا می‌شود.
:::

## جبر نقشه و طبقه‌بندی دوباره

**جبر نقشه** (map algebra) یعنی ساختن رستر تازه با عملیات ریاضی روی پیکسل‌ها؛ مثلاً NDVI از دو باند قرمز و فروسرخ (فصل ۳۵)، یا «مناطق
مناسب ساخت‌وساز = شیب کمتر از ۱۰ درجه و ارتفاع کمتر از ۱۴۰۰ متر». **طبقه‌بندی دوباره** (reclass) بازه‌های مقدار را به کلاس تبدیل می‌کند:

```{.sql .run setup=dem}
WITH s AS (SELECT ST_Slope(rast, 1, '32BF', 'DEGREES') AS slope FROM dem),
     c AS (SELECT ST_Reclass(slope, 1, '[0-5):1, [5-10):2, [10-90]:3', '8BUI', 0) AS cls FROM s)
SELECT (vc).value AS slope_class,
       CASE (vc).value WHEN 1 THEN 'هموار (۰ تا ۵)' WHEN 2 THEN 'ملایم (۵ تا ۱۰)' ELSE 'تند (۱۰ و بیشتر)' END AS label,
       (vc).count AS pixels,
       round((vc).count * 900 / 10000.0, 1) AS hectares
FROM (SELECT ST_ValueCount(cls) AS vc FROM c) x
ORDER BY 1;
```

`ST_ValueCount` تعداد پیکسل هر مقدار را می‌دهد و چون هر پیکسل ۳۰×۳۰ = ۹۰۰ متر مربع است، مساحت هر کلاس به دست می‌آید. با `ST_MapAlgebra`
دوباندی هم می‌توان دو رستر را ترکیب کرد:
`ST_MapAlgebra(slope, 1, dem, 1, 'CASE WHEN [rast1] < 10 AND [rast2] < 1400 THEN 1 ELSE 0 END')`.

## از رستر به برداری

`ST_DumpAsPolygons` پیکسل‌های هم‌مقدار مجاور را به چندضلعی تبدیل می‌کند؛ کاربرد اصلی‌اش تبدیل نقشه‌ی طبقه‌بندی‌شده به لایه‌ی برداری است:

```{.sql .run setup=dem}
WITH c AS (SELECT ST_Reclass(ST_Slope(rast, 1, '32BF', 'DEGREES'), 1, '[0-5):1, [5-10):2, [10-90]:3', '8BUI', 0) AS cls FROM dem)
SELECT (p).val AS slope_class,
       count(*) AS polygons,
       round(sum(ST_Area((p).geom)) / 10000) AS hectares
FROM (SELECT ST_DumpAsPolygons(cls) AS p FROM c) x
GROUP BY 1 ORDER BY 1;
```

جهت مخالف، **برداری به رستر**، با `ST_AsRaster(geom, …)` انجام می‌شود؛ مثلاً برای تبدیل مرز مناطق حفاظت‌شده به ماسک رستری.

## خروجی رستر

- `ST_AsPNG(ST_ColorMap(rast, 'elevation'))` تصویر رنگی PNG برای نمایش یا گزارش.
- `ST_AsGDALRaster(rast, 'GTiff')` فایل GeoTIFF (برای دانلود از برنامه).
- `gdal_translate` با `PG:"… table=dem"` رستر را مستقیم از پایگاه به هر قالب GDAL می‌برد.
- QGIS لایه‌های رستری PostGIS را مستقیم باز می‌کند (DB Manager یا Browser).

## رستر در پایگاه یا بیرون از آن؟

| | درون پایگاه (in-db) | بیرون پایگاه (out-db) یا فایل COG |
|---|---|---|
| پرسش و تلفیق با SQL | بسیار راحت | با `-R` ممکن، کندتر |
| حجم پایگاه و بکاپ | بزرگ | کوچک |
| مناسب برای | رسترهای کوچک و متوسط، نتیجه‌ی تحلیل، ماسک‌ها | تصویرهای بزرگ و سری زمانی ماهواره‌ای |
| در سامانه | افزونه‌ی رستر | بخش «تصویر ماهواره‌ای» و «رستر سازمانی» (فصل‌های ۳۴ و ۵۲) |

::: real
**مکان‌یابی پنل خورشیدی.** شرکتی برای یافتن زمین مناسب نیروگاه خورشیدی در یک استان، سه معیار دارد: شیب کمتر از ۵ درجه، جهت جنوبی (بین ۱۳۵ و
۲۲۵ درجه) و فاصله‌ی کمتر از ۵ کیلومتر از خط انتقال برق. با DEM استان در پایگاه، شیب و جهت با `ST_Slope` و `ST_Aspect`، ترکیب با
`ST_MapAlgebra`، تبدیل به چندضلعی با `ST_DumpAsPolygons` و فیلتر فاصله با `ST_DWithin` روی لایه‌ی خطوط برق، همه در یک اسکریپت SQL
تکرارپذیر انجام شد.
:::

::: summary
- نوع `raster` (افزونه‌ی postgis_raster) رستر را کاشی‌کاشی در جدول نگه می‌دارد؛ `ST_MetaData` مرجع مکانی را می‌دهد.
- `raster2pgsql -s -I -C -M -t` رستر را وارد می‌کند؛ `-R` آن را بیرون پایگاه نگه می‌دارد.
- `ST_Value` مقدار در نقطه، `ST_Clip` + `ST_SummaryStats` آمار ناحیه‌ای.
- `ST_Slope`، `ST_Aspect` و `ST_HillShade` تحلیل ارتفاع؛ DEM باید متری باشد.
- `ST_MapAlgebra` جبر نقشه، `ST_Reclass` طبقه‌بندی دوباره، `ST_ValueCount` مساحت کلاس‌ها، `ST_DumpAsPolygons` رستر به برداری.
- تصویرهای ماهواره‌ای سامانه فایل COG‌اند؛ افزونه‌ی رستر برای رسترهای خودتان در پایگاه.
:::

::: teach
**زمان پیشنهادی:** دو جلسه. اگر DEM واقعی یک منطقه را دارید (مثلاً از بخش «تصویر ماهواره‌ای» با محصول «ارتفاع (DEM)» و ورود با
raster2pgsql)، همین کدها را روی آن اجرا کنید؛ دیدن شیب و سایه‌روشن منطقه‌ی آشنا در QGIS بسیار جذاب است.
:::
