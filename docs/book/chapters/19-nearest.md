## پرسش «نزدیک‌ترین»

«نزدیک‌ترین بیمارستان به محل حادثه کجاست؟»، «برای هر مدرسه، نزدیک‌ترین ایستگاه مترو و فاصله‌اش؟»، «پنج شعبه‌ی نزدیک به این مشتری؟».
این‌ها پرسش‌های **نزدیک‌ترین همسایه** (k-Nearest Neighbors یا **KNN**) هستند و در هر سامانه‌ی خدمات مکانی هزاران بار در روز اجرا
می‌شوند.

راه ساده‌لوحانه این است که فاصله‌ی همه‌ی جفت‌ها را حساب و مرتب کنیم:

```sql
-- درست ولی کند: فاصله تا همه‌ی مراکز حساب و بعد مرتب می‌شود
SELECT name FROM health_centers
ORDER BY ST_Distance(geom, 'SRID=4326;POINT(51.40 35.72)'::geometry)
LIMIT 1;
```

برای ۴۰ مرکز مهم نیست؛ برای ۴۰ میلیون نقطه یعنی چند دقیقه. PostGIS عملگر ویژه‌ای دارد که این کار را با **شاخص** انجام می‌دهد.

## عملگر <->

عملگر `<->` فاصله‌ی دو هندسه را برمی‌گرداند، اما وقتی در `ORDER BY` با `LIMIT` بیاید و یک طرفش ستون شاخص‌دار باشد، PostGIS به جای
محاسبه‌ی همه‌ی فاصله‌ها، درخت شاخص را **از نزدیک به دور** پیمایش می‌کند و به محض یافتن k مورد متوقف می‌شود:

```{.sql .run}
SELECT name, type,
       round(ST_Distance(geom::geography, 'SRID=4326;POINT(51.40 35.72)'::geography)) AS meters
FROM health_centers
ORDER BY geom <-> 'SRID=4326;POINT(51.40 35.72)'::geometry
LIMIT 3;
```

الگوی کلی را به خاطر بسپارید: **مرتب‌سازی با `<->`، نمایش فاصله با `ST_Distance` روی geography.** `<->` روی geometry با SRID ۴۳۲۶
فاصله را به درجه می‌دهد؛ برای **ترتیب** کافی است (در فاصله‌های کوتاه ترتیب تقریباً درست است)، ولی برای **نمایش** باید فاصله‌ی متری
را جداگانه حساب کرد.

::: know
**درخت R و پیمایش «بهترین-اول».** شاخص GiST فضا را به مستطیل‌های تودرتو تقسیم می‌کند (فصل ۲۰). برای یافتن نزدیک‌ترین، الگوریتم از
ریشه شروع می‌کند و همیشه مستطیلی را باز می‌کند که کمترین فاصله را تا نقطه‌ی هدف دارد. مستطیل‌های دور هرگز باز نمی‌شوند. برای همین
زمان یافتن نزدیک‌ترین تقریباً مستقل از حجم جدول است.
:::

::: pro
**دقت ترتیب در geometry درجه‌ای.** در عرض تهران، یک درجه‌ی طول حدود ۹۰ و یک درجه‌ی عرض حدود ۱۱۱ کیلومتر است؛ پس `<->` روی ۴۳۲۶ فاصله‌ی
شمالی-جنوبی را کمتر از واقعیت وزن می‌دهد. وقتی دو نامزد فاصله‌ی نزدیک به هم در جهت‌های مختلف دارند، ترتیب ممکن است جابه‌جا شود. راه
مطمئن: چند نامزد بیشتر با `<->` بگیرید و آن‌ها را با فاصله‌ی دقیق دوباره مرتب کنید (الگوی «دو مرحله‌ای» پایین)، یا مستقیم روی
geography مرتب کنید: `ORDER BY geom::geography <-> point::geography` که با شاخص روی `(geom::geography)` سریع است.
:::

## برای هر سطر، نزدیک‌ترین: LATERAL

پرسش رایج‌تر این است: «برای **هر** مدرسه، نزدیک‌ترین ایستگاه مترو». در فصل ۱۳ دیدیم که `JOIN LATERAL` زیرپرسش را برای هر سطر اجرا
می‌کند:

```{.sql .run rows=5}
SELECT s.name AS school,
       m.name AS nearest_station, m.line,
       round(ST_Distance(s.geom::geography, m.geom::geography)) AS meters
FROM schools s
CROSS JOIN LATERAL (
  SELECT name, line, geom
  FROM metro_stations
  ORDER BY metro_stations.geom <-> s.geom
  LIMIT 1
) m
ORDER BY meters DESC
LIMIT 5;
```

دورترین مدرسه‌ها از مترو بالای فهرست‌اند. برای **k نزدیک‌ترین**، فقط `LIMIT 1` را به `LIMIT k` تغییر دهید. اگر جدول سمت راست ممکن است
برای سطری نتیجه نداشته باشد (مثلاً با فیلتر)، `LEFT JOIN LATERAL (…) ON true` بنویسید تا آن سطر حذف نشود.

### از نتیجه تا شاخص دسترسی

با همین الگو می‌توان یک **شاخص دسترسی** ساخت: میانگین فاصله تا نزدیک‌ترین خدمت، و درصد جمعیت (اینجا دانش‌آموز) در فاصله‌ی قابل
پیاده‌روی:

```{.sql .run}
WITH nearest AS (
  SELECT s.level, s.students,
         ST_Distance(s.geom::geography, h.geom::geography) AS meters
  FROM schools s
  CROSS JOIN LATERAL (SELECT geom FROM health_centers ORDER BY geom <-> s.geom LIMIT 1) h
)
SELECT level,
       round(avg(meters))                                                   AS avg_m_to_clinic,
       round(percentile_cont(0.9) WITHIN GROUP (ORDER BY meters))           AS p90_m,
       round(100.0 * sum(students) FILTER (WHERE meters <= 1000) / sum(students), 1) AS students_within_1km_pct
FROM nearest
GROUP BY level
ORDER BY level;
```

این پرسش در یک خط می‌گوید «چند درصد دانش‌آموزان هر مقطع تا یک کیلومتری یک مرکز درمانی درس می‌خوانند»؛ از آن نوع عددهایی که در
گزارش‌های برنامه‌ریزی خواسته می‌شود.

## نزدیک‌ترین با شرط

**فیلتر ویژگی:** «نزدیک‌ترین بیمارستان»، نه هر مرکزی:

```{.sql .run rows=3}
SELECT s.name, h.name AS nearest_hospital, h.meters
FROM schools s
CROSS JOIN LATERAL (
  SELECT name, round(ST_Distance(s.geom::geography, geom::geography)) AS meters
  FROM health_centers
  WHERE type = 'بیمارستان'
  ORDER BY geom <-> s.geom
  LIMIT 1
) h
ORDER BY s.gid
LIMIT 3;
```

**سقف فاصله:** «نزدیک‌ترین ایستگاه، اگر تا ۵۰۰ متر باشد؛ وگرنه هیچ». شرط فاصله را با `ST_DWithin` در `WHERE` زیرپرسش بگذارید و از `LEFT
JOIN LATERAL` استفاده کنید تا مدرسه‌های بی‌ایستگاه با NULL بیایند:

```{.sql .run}
SELECT count(*) FILTER (WHERE m.name IS NOT NULL) AS with_station_500m,
       count(*) FILTER (WHERE m.name IS NULL)     AS without_station_500m
FROM schools s
LEFT JOIN LATERAL (
  SELECT name FROM metro_stations
  WHERE ST_DWithin(geom::geography, s.geom::geography, 500)
  ORDER BY geom <-> s.geom
  LIMIT 1
) m ON true;
```

**عارضه‌ی هم‌جدول:** نزدیک‌ترین مدرسه‌ی **دیگر** به هر مدرسه (پیوند با خود؛ با شرط `gid <>` تا خودش انتخاب نشود). این پرسش پایه‌ی
**تحلیل نزدیک‌ترین همسایه** (Nearest Neighbor Index) در آمار فضایی است که نشان می‌دهد نقطه‌ها خوشه‌ای، تصادفی یا منظم پخش شده‌اند
(فصل ۲۱).

## الگوی دو مرحله‌ای برای دقت

وقتی دقت ترتیب مهم است (مثلاً هندسه‌های غیرنقطه‌ای بزرگ یا عرض جغرافیایی بالا)، با شاخص چند نامزد بگیرید و با فاصله‌ی دقیق
دوباره مرتب کنید:

```{.sql .run rows=3}
SELECT name, round(d) AS meters
FROM (
  SELECT name, ST_Distance(geom::geography, 'SRID=4326;POINT(51.40 35.72)'::geography) AS d
  FROM parks
  ORDER BY geom <-> 'SRID=4326;POINT(51.40 35.72)'::geometry
  LIMIT 10                 -- مرحله‌ی ۱: ده نامزد با شاخص
) candidates
ORDER BY d                 -- مرحله‌ی ۲: ترتیب دقیق
LIMIT 3;
```

برای چندضلعی‌ها، `<->` فاصله‌ی واقعی هندسه را برمی‌گرداند (نه فقط مستطیل محدوده)، ولی پیمایش شاخص بر پایه‌ی مستطیل‌هاست؛ الگوی
دو مرحله‌ای هم سرعت را حفظ می‌کند و هم ترتیب را تضمین. عملگر `<#>` فاصله‌ی **مستطیل‌های محدوده** را می‌دهد که از همه سریع‌تر ولی
تقریبی‌تر است.

## نزدیک‌ترین روی خط

گاهی «نزدیک‌ترین نقطه روی یک خط» لازم است، نه نزدیک‌ترین عارضه؛ مثلاً اتصال هر ساختمان به نزدیک‌ترین نقطه‌ی خیابان برای نشانی‌دهی
یا اتصال به شبکه‌ی مسیریابی. `ST_ClosestPoint(line, point)` و `ST_ShortestLine(line, point)` همین را می‌دهند (فصل ۱۶ و ۱۸) و در
فصل ۲۴ برای «چسباندن» مبدأ و مقصد به شبکه‌ی معابر از آن استفاده می‌کنیم.

::: warn
**فاصله‌ی هوایی، نه واقعی.** همه‌ی فاصله‌های این فصل **هوایی** (خط مستقیم) هستند. نزدیک‌ترین بیمارستان هوایی ممکن است آن سوی بزرگراه یا
رود باشد و با خودرو دورتر از دومی. برای دسترسی واقعی، فاصله را روی **شبکه‌ی معابر** حساب کنید (فصل‌های ۲۴ و ۲۸). فاصله‌ی هوایی برای
غربال اولیه و تحلیل‌های کلان مناسب است.
:::

::: try
برای هر ایستگاه مترو، سه مدرسه‌ی نزدیک و فاصله‌شان را بدهید. سپس ایستگاه‌هایی را پیدا کنید که نزدیک‌ترین مدرسه‌شان بیش از ۸۰۰ متر
فاصله دارد؛ این ایستگاه‌ها برای ساخت مدرسه‌ی تازه کاندیدند.
:::

::: summary
- `ORDER BY geom <-> X LIMIT k` با شاخص GiST نزدیک‌ترین‌ها را بدون محاسبه‌ی همه‌ی فاصله‌ها می‌یابد.
- ترتیب با `<->`، نمایش فاصله با `ST_Distance` روی geography.
- «برای هر سطر، نزدیک‌ترین» = `CROSS JOIN LATERAL (… ORDER BY <-> LIMIT k)`؛ با `LEFT JOIN LATERAL … ON true` سطرهای بی‌نتیجه می‌مانند.
- فیلتر ویژگی و سقف فاصله (`ST_DWithin`) داخل زیرپرسش LATERAL.
- الگوی دو مرحله‌ای: نامزدها با شاخص، ترتیب نهایی با فاصله‌ی دقیق.
- فاصله‌ی KNN هوایی است؛ دسترسی واقعی روی شبکه.
:::

::: teach
**زمان پیشنهادی:** یک جلسه. با `EXPLAIN ANALYZE` (فصل ۲۰) زمان پرسش ساده‌لوحانه و `<->` را روی جدولی بزرگ (مثلاً ساختمان‌های OSM از فصل
۳۰) مقایسه کنید؛ اختلاف چند صد برابری بهترین انگیزه برای یادگیری شاخص است.
:::
