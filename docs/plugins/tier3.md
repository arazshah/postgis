# پلاگین سطح ۳ (کد درون‌پردازه، تحویل از مسیر ایمیج)

مرجع تصمیم: `docs/adr/0007-tier3-in-process-plugins.md`. این راهنما برای **نویسنده‌ی تیم** است، نه مشتری.

## سطح ۳ یعنی چه؟
- کد پایتون و مدل و مهاجرت و نمای کامل جنگو که **در همان پردازه‌ی سایت** اجرا می‌شود (برخلاف سطح ۲ که در کانتینر ایزوله است).
- **هیچ جداسازی امنیتی ندارد.** محافظ‌ها: بازبینی دونفره‌ی PR، `ext_check`، قرارداد import، مهاجرت افزایشی، پیش‌پرواز شروع و قطع‌کن زمان اجرا.
- پس فقط برای کاری که سطح ۱ (صفحه‌ی اعلانی) و سطح ۲ (handler در جعبه) از پسش برنمی‌آیند؛ و فقط **کد تیم خودتان**.
- از پنل بارگذاری **نمی‌شود**. کد با PR وارد مخزن و ایمیج می‌شود؛ **فعال‌سازی** برای مشتری از پنل است.

## چرخه‌ی کار
1. `python manage.py ext_new <id> --name "نام فارسی"` ← داربست در `ext/<id>/` (apps، plugin، مدل نمونه، مهاجرت، نما، قالب، آزمون، README).
2. توسعه. بررسی محلی: `python manage.py ext_check <id>` و `python manage.py test ext.<id>`.
3. PR (بازبین دوم = اصل دونفره). CI: `test`، `ext-preflight` (ext_check، `check`، مهاجرت روی پایگاه خالی و از طرح `main` به جلو، آزمون‌های پلاگین، دود)، `docker` (سایت با پلاگین معیوب ساختگی بالا می‌آید).
4. مرج ← ایمیج ← **یک‌باره دیپلوی** (Coolify). پلاگین تازه **«محدود و بدون مجوز»** ظاهر می‌شود؛ هیچ مشتری نمی‌بیندش.
5. مدیر در «پلاگین‌ها و مجوزها» مجوز می‌دهد (همه، پلن، سازمان، کاربر یا یک پایگاه) یا از «افزونه‌های قابل خرید» می‌فروشد.
6. به‌روزرسانی = PR تازه با `version` بالاتر. خاموشی آنی = پنل. بازگشت نسخه = استقرار ایمیج قبلی.
7. حذف = برداشتن پوشه در PR (جدول‌ها می‌مانند). پاک‌سازی صریح پس از پشتیبان: `python manage.py ext_purge <id>` (پیش‌نمایش) و `--yes`.

## قرارداد
- پوشه `ext/<id>/`؛ `apps.py` با `name = "ext.<id>"` و `label = "x_<id>"` (جدول‌ها `x_<id>_*`)؛ `plugin.py` با `plugins.register("<id>", …, kind="custom", tier=3)`.
- مسیر فقط با `kernel.routes` در دو گروه: `ext` (آدرس `/x/<id>/…`) و `ws_ext` (آدرس `dashboard/<pk>/x/<id>/…`، دروازه‌ی مجوز فضای کار را می‌فهمد). مسیر باید با `<id>/` شروع شود. `urls.py` سراسری ندارد.
- فقط SDK هسته (`kernel.plugins/routes/nav/home/dash/jobs/events/settings/conf/metering/entitlements/gate/workspace/tenantdb/dataio/pagekit/…`) و برای کلید خارجی `databases.models`، `accounts.models`، `kernel.models`. اپ‌های دیگر و `kernel.crypto/pkg/runner/admin` ممنوع (`lint-imports`).
- نمای عمومی (مثلاً دریافت داده‌ی دستگاه) با `@gate.public` و احراز هویت خودش.
- مهاجرت فقط افزایشی (`CreateModel`، `AddField` با null/default، `AddIndex`، `AddConstraint`)؛ کلید خارجی فقط `CASCADE`/`SET_NULL` به مدل خودی، `UserDatabase`، `User`، `Organization`. عملیات ممتاز فقط با `# ext: privileged-migration` و در PR جدا.
- ممنوع: افزودن به `MIDDLEWARE`/`TEMPLATES`/تنظیم سراسری، سیگنال روی مدل غیرخودی (از `kernel.events` استفاده کنید)، `Meta.db_table`، `managed=False`، proxy، خواندن `SECRET_KEY`، `cursor()` خام. «هشدار» (`subprocess`، `pickle`، `ctypes`، `socket`، `eval`/`exec`، `os.system`) فقط با `# ext: allow(<دلیل>)` روی همان خط.

## سایت چگونه سر پا می‌ماند
| خرابی | رفتار |
|---|---|
| import معیوب یا مهاجرت خراب در شروع | `ext_preflight` در `entrypoint.sh`: همان پلاگین برای همین بوت کنار می‌رود (`PLUGINS_DISABLED`)؛ سایت بالا می‌آید؛ کارت داشبورد |
| ترکیب پلاگین‌ها ناسازگار | حالت امن: هیچ پلاگین سطح ۳ بار نمی‌شود |
| خطای پیاپی در زمان اجرا | قطع‌کن: ۲۰ اجرا، ۵۰٪ خطا، ۳۰ دقیقه ← خاموشی آنی + `PluginTrip` + اعلان. هر پلاگین جدا؛ ۴xx و درخواست غیرمجاز شمرده نمی‌شود؛ اگر چند پایگاه داده از پلاگین استفاده می‌کنند، خطا باید از دست‌کم دو پایگاه باشد |
| استثنا در سهم خانه/داشبورد/رویداد/پروفایل یا `visible` منو | همان سهم/بخش حذف می‌شود، صفحه نمی‌شکند، در قطع‌کن شمرده می‌شود |
| اضطرار | `PLUGINS_SAFE_MODE=1` در Coolify و راه‌اندازی دوباره |

## ریسک‌های باقی‌مانده (صادقانه)
حلقه‌ی بی‌پایان یا مصرف حافظه در یک نما مهار نمی‌شود (`gunicorn --timeout` پردازه را می‌کشد)؛ کد بدخواه تیم خودی را بازبینی انسانی باید بگیرد. دسترسی هر پلاگین سطح ۳ به پایگاه پنل با مدل‌های خودش است و قرارداد import مرز را نگه می‌دارد، نه جداسازی زمان اجرا.
