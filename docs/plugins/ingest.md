# دریافت داده‌ی دستگاه (`[[ingest]]`)

برای داده‌ای که **دستگاه یا سامانه‌ی بیرونی** می‌فرستد (مثلاً ردیاب GPS) و باید در جدول پایگاه داده‌ی مشتری بنشیند، بدون نیاز به کد سطح ۳.
مرجع: `docs/adr/0007` (تصمیم ۴) و `docs/plugins/page-kit.md`.

## اصل
**دستگاه هرگز SQL یا نام ستون نمی‌دهد.** توکن فقط یک (پایگاه، پلاگین، صفحه، نقطه) را باز می‌کند؛ هسته مقدارها را طبق فیلدهای اعلام‌شده
اعتبارسنجی می‌کند و با `INSERT` پارامتری، **همه یا هیچ** در یک تراکنش می‌نویسد (مثل `[[forms]]`). handler سطح ۲ (اختیاری) فقط بدنه را به ردیف تبدیل می‌کند.

## اعلام در صفحه
```toml
[[ingest]]
key = "track"
title = "دریافت موقعیت دستگاه"
table = "gps_points"          # جدول عادی موجود در پایگاه مشتری
max_rows = 100                # سقف ردیف در هر درخواست (۱ تا ۱۰۰۰)
rate = 60                     # سقف درخواست در دقیقه برای هر توکن (۱ تا ۶۰۰)
# handler = "parse_gps"       # اختیاری: بدنه‌ی غیر JSON را به {rows: [{...}]} تبدیل می‌کند (سطح ۲، با tests/parse_gps.toml)
fields = [
  { name = "device", kind = "text", label = "دستگاه", required = true, max = 40 },
  { name = "lat", kind = "number", label = "عرض", min = -90, max = 90, required = true },
  { name = "lon", kind = "number", label = "طول", min = -180, max = 180, required = true },
]
```
صفحه‌ی دارای `[[ingest]]` دست‌کم `need = "editor"` می‌خواهد؛ حداکثر ۲ نقطه در هر صفحه. فیلدها همان انواع `[[forms]]` هستند.

## توکن
- فقط **مالک پایگاه داده** در همان صفحه‌ی پلاگین توکن می‌سازد و باطل می‌کند (حداکثر ۵ توکن فعال برای هر نقطه). توکن (`gpi_…`) **یک‌بار** نشان داده می‌شود؛ فقط SHA-256 آن ذخیره می‌شود.
- توکن در هدر `Authorization: Bearer <توکن>` می‌آید، نه در نشانی (تا در لاگ‌ها نماند).

## درخواست دستگاه
```
POST /ingest/
Authorization: Bearer gpi_…
Content-Type: application/json

[{"device": "d1", "lat": 35.7, "lon": 51.4}, {"device": "d2", "lat": 35.8, "lon": 51.5}]
```
پاسخ: `200 {"ok": true, "inserted": 2}`. شیء تکی هم پذیرفته می‌شود؛ فیلد اضافه نادیده گرفته می‌شود.

| کد | معنا |
|---|---|
| 200 | همه‌ی ردیف‌ها نوشته شد |
| 400 / 413 / 415 | بدنه خالی، بزرگ‌تر از ۲۵۶ کیلوبایت یا بیش از `max_rows`، یا غیر JSON (بدون handler) |
| 404 | توکن نامعتبر/باطل، پلاگین خاموش یا بدون مجوز، پایگاه غیرفعال (**همه یکسان**) |
| 422 | ردیف نامعتبر (پیام شماره‌ی ردیف)، یا پایگاه داده ردیف‌ها را نپذیرفت؛ **هیچ ردیفی نوشته نمی‌شود** |
| 429 | سقف درخواست در دقیقه، سقف ماهانه‌ی مجوز (`ingest_rows`) یا تلاش ناموفق زیاد از یک نشانی |
| 503 | نقطه درست پیکربندی نشده (جدول یا ستون در پایگاه نیست) |

## امنیت (خلاصه)
- نشانی عمومی است و فقط با توکن باز می‌شود؛ بدون CSRF (احراز هویت = توکن). خطاهای احراز هویت یکسان‌اند و تلاش ناموفق بر نشانی محدود می‌شود.
- نوشتن فقط INSERT در جدول عادی اعلام‌شده؛ ستون تولیدشده/identity/هندسه رد می‌شود؛ مقدارها همه پارامتر متصل‌اند.
- مصرف (`ingest_rows`) با `kernel.metering` شمرده و با سقف مجوز سنجیده می‌شود؛ اجرای handler در قطع‌کن خودکار می‌آید.
- حجم و ردیف و نرخ سقف دارند. ریسک باقی‌مانده: توکن لورفته تا ابطال می‌تواند در همان جدول ردیف بنویسد؛ ابطال از صفحه‌ی پلاگین آنی است.

## هنوز نیست
بدنه‌ی چندبخشی/باینری بزرگ، تأیید امضای HMAC هر پیام، ورود دسته‌ای زمان‌بندی‌شده، نمایش وضعیت دستگاه‌ها در پنل مدیر.
