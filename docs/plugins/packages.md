# بسته‌ی پلاگین: ساخت، امضا، بارگذاری و فعال‌سازی

مرجع: `docs/adr/0002-plugin-platform.md` و `docs/adr/0004-kernel-and-plugins.md`. در این مرحله **فقط پلاگین اعلانی (tier = 1)**
پشتیبانی می‌شود: بسته هیچ کد پایتونی ندارد و فقط صفحه‌ی کیت صفحه (`docs/plugins/page-kit.md`) می‌آورد.

## ساختار بسته (`.gpkgx` = zip)
```
plugin.toml          # مانیفست
pages/<کلید>.toml    # هر صفحه (مشخصات کیت صفحه)
README.md            # اختیاری
SIGNATURE            # JSON امضا (plugin_pack می‌سازد)
```
هر فایل دیگری (از جمله `.py`) رد می‌شود. حداکثر ۲ مگابایت، ۶۰ فایل، هر فایل ۲۰۰ کیلوبایت.

```toml
id = "fleet"                     # یکتا؛ با پلاگین داخلی برخورد نکند
name = "پایش ناوگان"
version = "1.0.0"                # عددی؛ هر نسخه‌ی تازه باید بالاتر از قبلی‌ها باشد
api = 1
kind = "custom"                  # custom | feature (system از راه بسته نمی‌آید)
tier = 1
requires = ["databases"]         # پلاگین‌های نصب‌شده‌ی مورد نیاز
[contributes]
pages = ["pages/live.toml"]      # باید دقیقاً با فایل‌های pages/ یکی باشد
```

## امضا (الزامی)
- کلید **Ed25519** ناشر: `python manage.py plugin_keygen geopaygah --out publisher.key` (کلید خصوصی فقط در CI مخزن پلاگین‌ها؛ هرگز commit نشود).
- خط کلید عمومی (`geopaygah=<base64>`) را مدیر استقرار در **متغیر محیطی** `PLUGIN_PUBLISHER_KEYS` می‌گذارد (چند ناشر با ویرگول).
  کلید عمداً در پایگاه داده نیست: حساب مدیر لورفته نمی‌تواند ناشر تازه اضافه کند.
- ساخت و امضا: `python manage.py plugin_pack <پوشه> --key publisher.key --publisher geopaygah --out fleet-1.0.0.gpkgx`
  (بررسی ایستا را هم نشان می‌دهد). بررسی یک بسته با کلیدهای همین استقرار: `python manage.py plugin_check fleet-1.0.0.gpkgx`.
- امضا روی چکیده‌ی **مسیر و محتوای همه‌ی فایل‌ها** است؛ تغییر یک بایت یا جابه‌جایی فایل بسته را رد می‌کند.

## چرخه‌ی عمر در پنل مدیریت («پلاگین‌ها و مشتریان سازمانی ← بارگذاری و نسخه‌ها»)
1. **بارگذاری** (مجوز `upload_pluginrelease`): بررسی خودکار فوراً اجرا می‌شود و گزارش هر مرحله ثبت می‌ماند، حتی برای بسته‌ی ردشده:
   بازکردن امن zip (مسیر، پیوند نمادین، حجم واقعی، بمب فشرده) ← امضا و ناشر ← مانیفست ← هویت و نسخه ← مشخصات صفحه‌ها.
   اولین شکست بقیه‌ی مرحله‌ها را متوقف می‌کند. بسته‌ی بدون امضای معتبر حتی خوانده نمی‌شود.
2. **تأیید و فعال‌سازی** (مجوز `activate_pluginrelease`): **اصل دونفره**: بارگذارنده نمی‌تواند خودش تأیید کند
   (تیم یک‌نفره با `PLUGIN_SELF_APPROVAL=1` می‌تواند این را بردارد). بسته پیش از فعال شدن دوباره بررسی می‌شود (ممکن است کلید ناشر حذف شده باشد).
3. پلاگین تازه با وضعیت **«محدود و بدون مجوز»** ساخته می‌شود: هیچ مشتری آن را نمی‌بیند تا مدیر در «پلاگین‌ها و مجوزها» مجوز بدهد
   (به کاربر، سازمان، پلن یا یک پایگاه داده؛ با انقضا).
4. **بازگشت**: نسخه‌ی قبلی (جایگزین‌شده) را دوباره «فعال‌سازی» کنید. **غیرفعال‌سازی** پلاگین را از رجیستری برمی‌دارد.
نسخه‌ها هرگز حذف نمی‌شوند (ردپا). هر پردازه ظرف حداکثر ۲۰ ثانیه تغییر را می‌گیرد، بدون راه‌اندازی دوباره.

## ایمنی
- محتوای اعلانی کد اجرا نمی‌کند؛ SQL صفحه‌ها فقط‌خواندنی و با نقش محدود مشتری اجرا می‌شود (جزئیات در `page-kit.md`).
- بسته‌ی فعال که بعداً بارگذاری‌اش خطا بدهد سایت را نمی‌خواباند: خطا در «سلامت» پلاگین دیده می‌شود.
- ورود دومرحله‌ی پنل (TOTP، `accounts/admin_2fa.py`) فعال است و بارگذاری و فعال/غیرفعال‌سازی نسخه «تأیید تازه» (۳۰ دقیقه‌ی اخیر، `kernel.stepup`) می‌خواهد. بازنشانی: `manage.py admin_2fa_reset <نام‌کاربری>`.

## تنظیمات هر پلاگین (`kernel.conf`)
پلاگین گزینه‌هایش را در `plugin.py` اعلام می‌کند و با `conf.get("<id>", "<کلید>")` می‌خواند:
```python
from kernel import conf
conf.option("fleet", "interval", "فاصله‌ی به‌روزرسانی (ثانیه)", kind="int", default=30, min=5, max=3600)
conf.option("fleet", "api_key", "کلید سرویس", kind="secret")   # str | int | bool | choice | secret
```
مدیر مقدارها را از «پلاگین‌ها و مجوزها ← پلاگین ← تنظیمات پلاگین» می‌دهد. مقدار `secret` رمزنگاری ذخیره می‌شود، هرگز در فرم نشان داده نمی‌شود
(فقط «تنظیم شده»؛ خالی‌گذاشتن = بدون تغییر) و تغییرش تأیید تازه (`kernel.stepup`) می‌خواهد. مقدار خراب به پیش‌فرض برمی‌گردد و استثنا نمی‌دهد.

## سنجش مصرف (`kernel.metering`)
- `metering.record("<id>", "<معیار>", n, user=, ws=)` شمارنده‌ی روزانه را زیاد می‌کند و **هرگز استثنا نمی‌دهد**. صفحه‌های کیت صفحه خودکار `page_views` را ثبت می‌کنند (تازه‌سازی خودکار شمرده نمی‌شود).
- سقف ماهانه از «سقف‌ها»ی مجوز می‌آید با کلید `<معیار>_per_month` (مثلاً `{"page_views_per_month": 5000}`)؛ نبودن = نامحدود. `metering.check(...)` می‌گوید زیر سقف هست یا نه؛ اعمالش با پلاگین است (صفحه‌های کیت، پر شدن سقف را رد می‌کنند).
- گزارش فقط‌خواندنی: پنل مدیریت ← «مصرف پلاگین‌ها». نگه‌داری ۴۰۰ روز (`metering.prune`). صورتحساب بعداً از همین شمارنده‌ها می‌خواند.

## فروش پلاگین (اتصال به صورتحساب)
- مدیر در «پنل ← مالی ← افزونه‌های قابل خرید» یک **افزونه** تعریف می‌کند: پلاگین، قیمت، مدت، دارنده (یک پایگاه داده یا حساب کاربر) و سقف‌ها (مثلاً `{"page_views_per_month": 5000}`). فقط پلاگین نصب‌شده‌ی غیرسیستمی فروخته می‌شود.
- مشتری از «خرید پلن ← افزونه‌ها» فاکتور (نوع «خرید افزونه») می‌سازد و با همان درگاه/رسید پلن‌ها می‌پردازد.
- پس از تأیید پرداخت، `kernel.entitlements.grant(...)` مجوز با منبع «خرید» می‌دهد؛ تمدید، انقضا را **به انتهای مجوز فعلی** اضافه می‌کند (نه از نو). اعمال تکراری فاکتور بی‌اثر است.
- برای اینکه خرید معنی داشته باشد، پلاگین را در «پلاگین‌ها و مجوزها» روی «محدود» بگذارید؛ مشتریِ بدون مجوز آن را نمی‌بیند.

## استودیوی ساخت پلاگین (پنل ← «استودیوی پلاگین»)
برای ساخت پلاگین اعلانی بدون نوشتن دستی `plugin.toml`: مشخصات را در فرم بنویسید (مانیفست خودکار ساخته و با فایل‌های صفحه همگام می‌شود)، صفحه را از قالب «پایش» یا «فرم ثبت» بیفزایید، «ذخیره و بررسی» همان بررسی بسته را نشان می‌دهد (مانیفست، شناسه، صفحه‌ها، دسترسی نوشتن).
- **پیش‌نمایش** روی یک پایگاه داده‌ی فعال: فقط‌خواندنی با نقش محدود، فرم‌ها اجرا نمی‌شوند؛ تأیید تازه می‌خواهد و در گزارش فعالیت ثبت می‌شود.
- **خروجی** پوشه‌ی zip **بدون امضا** است: باز کنید و در CI با `manage.py plugin_pack` امضا کنید، سپس از «بارگذاری و نسخه‌ها» بارگذاری شود. کلید ناشر روی سرور نیست، پس استودیو راهی برای دور زدن امضا یا اصل دونفره نیست.
- دسترسی: همان مجوز `upload_pluginrelease`.
