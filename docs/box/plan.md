# طرح «جعبه‌ی ژئوپایگاه» (PostGIS Box) روی NanoPi NEO3 (۲ گیگ)

> وضعیت: پیش‌نویس فاز صفر — بررسی و تصمیم‌گیری. هنوز کدی برای جعبه نوشته نشده است.
> هدف فاز ۱: کارت SD را می‌نویسیم، دستگاه را به شبکه وصل می‌کنیم، در مرورگر `http://postgisbox.local`
> را می‌زنیم و با نام کاربری و رمز پیش‌فرض وارد پنل می‌شویم — **بدون هیچ اتصال اینترنتی**.

---

## ۱. نکته‌های پایه که باید از اول درست فهمیده شوند

| موضوع | واقعیت | پیامد |
|---|---|---|
| قالب ایمیج | بردهای ARM مثل NEO3 فایل **ISO** ندارند؛ خروجی یک فایل **`.img.xz`** است (مثل DietPi و Armbian) | کاربر با balenaEtcher / Raspberry Pi Imager / Rufus آن را روی SD می‌نویسد؛ بوت‌لودر (U-Boot) داخل همان ایمیج است |
| پردازنده | Rockchip RK3328، چهار هسته Cortex-A53 (arm64/aarch64) | همه‌ی بسته‌ها و چرخ‌های پایتون باید aarch64 باشند؛ ایمیج‌های فعلی GHCR فقط amd64 هستند |
| حافظه | ۲ گیگابایت DDR4 | QGIS Server + PostgreSQL + gunicorn با هم جا نمی‌شوند مگر با تنظیم دقیق؛ Docker سربار اضافه دارد |
| خروجی تصویر | NEO3 **HDMI ندارد** و WiFi هم ندارد | کاربر هیچ صفحه‌ای روی خود دستگاه نمی‌بیند؛ پیدا کردن دستگاه در شبکه باید بی‌نیاز از تنظیم باشد |
| ساعت | **RTC (باتری ساعت) ندارد** | بدون اینترنت (NTP) ساعت بعد از هر خاموشی عقب می‌رود → اعتبار نشست، کد یکبارمصرف، زمان بکاپ و گواهی TLS به هم می‌ریزد |
| ذخیره‌سازی | فقط microSD + یک درگاه USB 3.0 | SD برای پایگاه داده کند است و فرسوده می‌شود؛ دیسک USB (SSD) برای داده توصیه می‌شود |
| دکمه | یک دکمه‌ی کاربر (K1) روی برد هست | می‌شود از آن برای «بازنشانی رمز مدیر» استفاده کرد (در سخت‌افزار واقعی باید تأیید شود) |

## ۲. معماری پیشنهادی

### ۲-۱. سیستم‌عامل پایه: Armbian (Debian) با ساخت از پیش (pre-baked)
- **DietPi** الهام‌بخش خوبی است (کمینه، `dietpi.txt` برای تنظیم پیش از بوت، راه‌اندازی خودکار)، ولی نصب نرم‌افزار در DietPi
  در **اولین بوت** و با **اینترنت** انجام می‌شود؛ این با هدف «کاملاً آفلاین» نمی‌خواند.
- پیشنهاد: **Armbian Build Framework** برای برد `nanopineo3`، شاخه‌ی Debian (Trixie؛ اگر هسته‌ی برد آنجا پایدار نبود Bookworm)،
  نسخه‌ی minimal، و نصب همه‌ی نرم‌افزارها **در زمان ساخت ایمیج** با `userpatches/customize-image.sh`.
  نتیجه: ایمیجی که در اولین بوت فقط «شخصی‌سازی» می‌کند (رمزهای یکتا، گسترش پارتیشن)، نه دانلود.
- از DietPi این ایده‌ها را برمی‌داریم: فایل تنظیم قابل ویرایش روی پارتیشن boot (`geobox.txt`)، لاگ در RAM،
  zram به‌جای swap روی SD، سرویس‌های کمینه.

### ۲-۲. اجرای برنامه: بومی با systemd (نه Docker) — پیشنهاد
| | بومی (systemd) | Docker |
|---|---|---|
| حافظه | کمتر (بدون daemon و لایه‌های تکراری) | ۱۵۰–۳۰۰ مگ بیشتر |
| نوشتن روی SD | کمتر | overlayfs و لاگ کانتینرها |
| ایمیج arm64 | بسته‌های Debian: `postgresql-17-postgis-3`، `-pgrouting`، `-pgvector`، `gdal-bin`، `osmium-tool`، `qgis-server` همه برای arm64 هستند | `postgis/postgis` و `pgrouting/pgrouting` ایمیج arm64 رسمی ندارند؛ باید خودمان بسازیم |
| هم‌خوانی با ابر | کمتر (باید یک لایه‌ی systemd نگه داریم) | بیشتر |

تصمیم پیشنهادی: **بومی**. کد Django همان است؛ فقط اسکریپت راه‌اندازی (`docker/entrypoint.sh`) به یک
`geobox-init` و چند unit systemd تبدیل می‌شود.

### ۲-۳. اجزای روی دستگاه
```
                    LAN (کابل شبکه، DHCP)
                          │
   ┌──────────────────────┴──────────────────────────────┐
   │ avahi (mDNS: postgisbox.local) + LLMNR (postgisbox) │
   │ nginx :80/:443  ── استاتیک /static و /media          │
   │      └── gunicorn (geobox-web) 2 worker × 4 thread   │
   │ geobox-worker  (python manage.py run_worker)         │
   │ PostgreSQL 17 + PostGIS + pgRouting + pgvector :5432 │
   │      ├── دیتابیس panel (پنل)                         │
   │      └── دیتابیس‌های gp_* (پایگاه‌های کاربران)       │
   │ qgis-server (fcgi) — فاز ۲، پیش‌فرض خاموش            │
   └──────────────────────────────────────────────────────┘
```
- **یک خوشه‌ی PostgreSQL** هم برای پنل و هم برای پایگاه‌های کاربران (در ابر جداست؛ اینجا برای صرفه‌ی حافظه یکی).
  نقش ادمین جدا (`geobox_admin`) با CREATEDB/CREATEROLE که پنل با آن پایگاه می‌سازد؛ نقش `panel` فقط مالک دیتابیس پنل.
- پایگاه‌های کاربران روی LAN باز است تا QGIS/ArcGIS از رایانه‌ها وصل شوند (`listen_addresses='*'`،
  `pg_hba` فقط شبکه‌های خصوصی 10/8، 172.16/12، 192.168/16 با scram).
- تنظیم حافظه برای ۲ گیگ (نقطه‌ی شروع): `shared_buffers=256MB`، `effective_cache_size=1GB`، `work_mem=8MB`،
  `maintenance_work_mem=128MB`، `max_connections=60`، `max_worker_processes=4`، `wal_compression=on`،
  `random_page_cost=1.5` (روی SSD) — بعد با سنجش واقعی اصلاح شود.

### ۲-۴. ساختار پوشه‌ها روی دستگاه
```
/opt/geobox/releases/<نسخه>/   کد + venv (فقط‌خواندنی)
/opt/geobox/current  ->  releases/<نسخه>    (به‌روزرسانی اتمی و برگشت)
/etc/geobox/geobox.env          رمزها و تنظیمات تولیدشده در اولین بوت (۰۶۰۰)
/var/lib/geobox/{media,backups,ows,osm,rasters}   داده (روی SSD اگر وصل باشد)
/boot/geobox.txt                تنظیم پیش از بوت: نام دستگاه، IP ثابت، رمز اولیه، منطقه‌ی زمانی
```

## ۴. پیدا کردن دستگاه در شبکه (نام کوتاه)

بدون HDMI، این مهم‌ترین تجربه‌ی کاربر است. چند لایه با هم:
1. **mDNS (avahi):** `http://postgisbox.local` — ویندوز ۱۰/۱۱، مک، iOS، لینوکس و اندروید جدید بدون نصب چیزی.
2. **LLMNR (systemd-resolved):** ویندوز نام تک‌کلمه‌ای `http://postgisbox/` را هم پیدا می‌کند.
3. **WS-Discovery (`wsdd`):** دستگاه در «Network» ویندوز دیده می‌شود.
4. **نام DHCP:** دستگاه نامش را به روتر می‌دهد؛ در شبکه‌هایی که روتر DNS محلی دارد، `postgisbox` یا `postgisbox.lan` هم کار می‌کند.
   مدیر شبکه‌ی سازمان هم می‌تواند یک رکورد A در DNS خودش بزند (همان «دادن DNS»).
5. **اتصال مستقیم کابل به لپ‌تاپ (بدون روتر):** آدرس link-local (`169.254.x.x`) با avahi-autoipd + mDNS.
6. **IP ثابت اختیاری** از `geobox.txt` روی کارت (قبل از بوت با هر رایانه‌ای قابل ویرایش).
7. اگر چند جعبه در یک شبکه باشد، avahi خودش `postgisbox-2.local` می‌دهد؛ بهتر: نام = `postgisbox` + ۴ رقم آخر MAC روی برچسب.

**نام پیشنهادی:** `postgisbox` گویا است؛ گزینه‌های کوتاه‌تر: `geobox`، `gpbox`، `pgbox`. (پرسش ۲)

## ۵. اولین بوت (`geobox-firstboot.service`، یک بار)
1. گسترش پارتیشن روی کل کارت (Armbian خودش انجام می‌دهد).
2. ساخت **رمزهای یکتای هر دستگاه** — هیچ رمزی داخل ایمیج نیست:
   `DJANGO_SECRET_KEY`، `CREDENTIALS_ENCRYPTION_KEY`، رمز نقش‌های PostgreSQL، کلیدهای میزبان SSH، `machine-id`.
3. خواندن `/boot/geobox.txt` (نام، IP، منطقه‌ی زمانی، رمز اولیه‌ی مدیر).
4. اگر دیسک USB با برچسب `GEOBOX-DATA` وصل است: داده روی آن (فرمت فقط با تأیید صریح).
5. `initdb` با تنظیمات ۲ گیگ، ساخت دیتابیس پنل، `migrate`، `seed_defaults`، `kb_sync`، `gnss_sync`، `ensure_superuser`،
   ثبت سرور محلی (`add_server --default`).
6. ساخت گواهی TLS محلی (اگر HTTPS انتخاب شد).
7. چشمک LED سبز = آماده. (کل فرایند روی RK3328 حدود ۲–۴ دقیقه؛ صفحه‌ی «در حال آماده‌سازی» به‌جای خطای 502.)

**ورود پیش‌فرض:** `admin` / `postgisbox` (یا هر چه در `geobox.txt` باشد) → اجبار به تغییر رمز در اولین ورود.
**بازنشانی:** نگه‌داشتن دکمه‌ی K1 به مدت ۱۰ ثانیه = بازگشت رمز مدیر به پیش‌فرض (نه پاک کردن داده).

## ۶. داده، کارت SD و پایداری
- کارت **A2 / High Endurance** حداقل ۳۲ گیگ؛ برای کار جدی **SSD روی USB 3.0** (سرعت چند برابر و عمر بسیار بیشتر).
- لاگ در RAM (`armbian-ramlog`/log2ram)، `journald` با سقف حجم، zram برای swap، `noatime`.
- خاموشی ناگهانی برق رایج است: PostgreSQL با `fsync=on` می‌ماند؛ فایل‌سیستم ext4 با journal. (آداپتور برق ۵ ولت ۲ آمپر باکیفیت ضروری.)
- بکاپ شبانه‌ی فعلی (`run_worker`) → مقصد دیسک USB؛ دانلود بکاپ از پنل.
- سقف‌ها برای ۲ گیگ: `IMPORT_MAX_MB`، `RASTER_MAX_MB`، تعداد کار هم‌زمان worker = ۱.

## ۷. امنیت
- رمز پیش‌فرض شناخته‌شده است → اجبار به تغییر، قفل پس از تلاش ناموفق (منطق `admin_auth.py` به ورود کاربر هم برسد).
- SSH پیش‌فرض **خاموش** (روشن‌کردن از `geobox.txt` یا پنل)؛ کاربر root بی‌رمز وجود ندارد.
- دستگاه برای LAN است؛ در راهنما صریح بگوییم پورت ۵۴۳۲ را روی اینترنت باز نکنند.
- رمزهای یکتا در اولین بوت (بند ۵) — بزرگ‌ترین خطای رایج جعبه‌ها همین رمز مشترک در همه‌ی دستگاه‌هاست.

## ۸. به‌روزرسانی آفلاین (طراحی از حالا، ساخت در فاز ۲)
- بسته‌ی به‌روزرسانی: `geobox-update-<نسخه>.tar` شامل کد + venv + مایگریشن، **امضاشده** (ed25519؛ کلید عمومی داخل ایمیج).
- راه رساندن: بارگذاری در پنل مدیر یا فلش USB.
- اعمال: باز کردن در `releases/<نسخه>`، بکاپ پنل، `migrate`، تعویض symlink، راه‌اندازی دوباره؛ در خطا برگشت خودکار.
- به‌روزرسانی سیستم‌عامل (apt) در فاز بعد، با همین سازوکار یا ایمیج تازه.

## ۹. خط تولید ایمیج (CI)
1. **ساخت چرخ‌های aarch64** برای `requirements.txt` (GitHub Actions با رانر `ubuntu-24.04-arm`) و ساختن venv.
   بسته‌های سنگین (numpy، rasterio زیر rio-tiler، Pillow، psycopg، cryptography) چرخ manylinux aarch64 دارند؛
   `smart-spatial-system` و `pmtiles` باید بررسی شوند. `collectstatic` همان‌جا.
2. **Armbian build** (روی x86 با Docker + qemu، یا روی رانر arm) با `BOARD=nanopineo3 BRANCH=current RELEASE=trixie BUILD_MINIMAL=yes`
   و `userpatches/customize-image.sh` که بسته‌های Debian و venv را نصب و سرویس‌ها را فعال می‌کند.
3. خروجی: `geobox-<نسخه>-nanopineo3.img.xz` + `sha256` → GitHub Releases.
4. آزمون: بوت ایمیج در QEMU (arm64 generic) برای دود-آزمون سرویس‌ها؛ آزمون نهایی روی برد واقعی.
- محل در مخزن (پیشنهاد): پوشه‌ی `box/` (اسکریپت‌ها، unitها، `userpatches`) و workflow جدا `box.yml`.

## ۱۱. خطرها
- **پشتیبانی Armbian از NEO3** در سطح «community» است؛ اگر هسته‌ی تازه مشکل داشت، شاخه‌ی قدیمی‌تر یا ایمیج پایه‌ی DietPi
  (که NEO3 را رسمی پشتیبانی می‌کند) با نصب از پیش جایگزین است. فاز ۰ همین را روشن می‌کند.
- **۲ گیگ RAM:** کارهای سنگین (درون‌ریزی OSM کل ایران، `osm2pgrouting`، رستر بزرگ، QGIS Server) ممکن است کند یا ناممکن باشند؛
