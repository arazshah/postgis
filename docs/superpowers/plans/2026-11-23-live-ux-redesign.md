# برنامهٔ پیاده‌سازی بازطراحی PostGIS Live

> برای عامل اجرا: پس از تأیید کاربر، از `superpowers:executing-plans` برای اجرای مرحله‌به‌مرحله استفاده شود. بررسی مستقل طراحی و بررسی امنیتی تغییرات ورود جزو برنامه است. هیچ مرحلهٔ اجرایی در این نشست شروع نشده است.

**هدف:** تبدیل Live به محیط GIS فارسی یکپارچه با ظاهر روشن و ساختار ArcGIS Pro و تکمیل کارهای روزمره در همان محیط.

**معماری:** حفظ Django، MapLibre، WebMap، SDK و صف موجود؛ پوسته و اجزای متمرکز Live، قرارداد درخواست/وضعیت مشترک و adapter برای سرویس‌های محصول. به‌جای گسترش فایل فشردهٔ فعلی، مسئولیت‌های رابط به ماژول‌های کوچک در `static/live/` تقسیم می‌شود؛ ابزار build جدید فقط در صورت نیاز اثبات‌شده افزوده شود.

**پشته:** Python/Django، قالب Django، JavaScript، CSS، MapLibre؛ آزمون Django و مرورگر واقعی با Playwright.

**سند مبنا:** [بررسی و طرح](../specs/2026-11-23-live-ux-redesign.md).

**وضعیت:** تأییدشده توسط کاربر در ۲۰۲۶-۱۱-۲۳؛ اجرا شروع شد. این تأیید، شروع پیاده‌سازی را مجاز می‌کند؛ انتشار production و تغییر DNS در این برنامه خودکار انجام نمی‌شود.

## محدودیت‌ها

- مرجع، ArcGIS Pro روشن و چیدمان استاندارد آن با متن فارسی/RTL است؛ موارد LTR مانند نام فنی و مختصات جدا می‌مانند.
- کد مبنا `origin/main` با Live است؛ شاخهٔ کنونی Live ندارد و تغییرات قبلی کاربر باید حفظ شوند.
- رعایت `docs/design-system.md` و ثبت گونهٔ فشردهٔ Live؛ فونت و آیکون محلی/مشترک.
- تمام جریان‌های جدول سند مبنا در دامنه‌اند؛ پرداخت و عملیات دستگاهی فقط با مسیر صریح و بازگشت روشن خارج می‌شوند.
- مدل پروژه، سهمیه و مجوز محصول موجود مرجع‌اند؛ حساب، موتور تحلیل یا سیستم مجوز موازی ساخته نشود.
- کنترل ظاهری بدون پشتیبانی ذخیره/اجرا تحویل نشود. ورود iframe کل صفحات، پیاده‌سازی این طرح محسوب نمی‌شود.
- TDD: آزمون رفتار ابتدا شکست بخورد، سپس حداقل تغییر و بازآرایی؛ تست بصری از سناریوی واقعی و screenshot بررسی‌شده استفاده کند.
- فایل‌های تولیدی، تنظیمات استقرار و دادهٔ واقعی تا تأیید تغییر نمی‌کنند.

## تمرکز بررسی و آزمون رگرسیون

۱. نام فارسی بلند، نیم‌فاصله، mixed LTR/RTL و چند schema هم‌نام → عنوان کامل، هویت درست و فونت صحیح؛ مالک: مراحل ۲ و ۳.
۲. viewer، فضای کار مشترک/غیرمجاز و قابلیت غیرفعال → کنترل روشن و پاسخ سرور مجاز؛ مالک: مراحل ۴ تا ۸.
۳. انقضای نشست وسط ذخیره/ابزار و تغییر حساب → حفظ فرم بدون افشای داده یا اجرای تکراری؛ مالک: مراحل ۴ و ۶.
۴. شبکهٔ کند، پاسخ خارج از ترتیب و دو Job هم‌زمان → dirty درست، جدول و تاریخچهٔ پایدار؛ مالک: مراحل ۲ و ۶.
۵. ۴۰۰px، zoom ۲۰۰٪ و صفحه‌کلید → بستن پنل و دسترسی به کار اصلی بدون گیرکردن؛ مالک: مراحل ۲، ۳، ۵ و ۹.

## ساختار و قراردادهای پیشنهادی

مسیرهای تازه در زمان اجرا از مبنای به‌روز ساخته می‌شوند؛ مسیرهای موجود زیر در `origin/main` بررسی شده‌اند.

| فایل/ماژول | مسئولیت |
|---|---|
| `templates/live/studio.html`, `index.html` | قاب معنایی و اتصال منابع، بدون منطق کسب‌وکار |
| `static/live/live.css` و فایل تازهٔ `fonts.css` | چیدمان و گونهٔ فشردهٔ Live؛ @font-face مستقل از CSS عمومی صفحه‌های سایت |
| `static/live/live.js` | نقطهٔ شروع و اتصال اجزا |
| تازه: `state.js`, `client.js`, `commands.js`, `panels.js` | وضعیت پروژه/درخواست/فرمان‌ها/پنل‌ها |
| تازه: `layers.js`, `properties.js`, `tools.js`, `results.js`, `auth.js`, `workflows.js` | محتویات، draft تنظیمات، فرم SDK، جدول/کارها، ورود و مسیرهای داخلی |
| `live/views.py`, `urls.py`, تازه: `api.py` و `auth.py` | adapterهای JSON و صفحهٔ Live؛ کنترل مجوز در سرور |
| `live/sso.py`, `accounts/views.py` | قرارداد نشست؛ استخراج سرویس مشترک حساب فقط در صورت ضرورت، با تست رفتار فعلی |
| `core/icons.py`, `static/js/studio-ui.js`, `static/js/ui.js` | آیکون/مودال/منوی مشترک؛ اصلاح حداقلی و با آزمون رگرسیون |
| `static/js/map-page.js`, `maps/views.py`, `maps/services.py` | اتصال renderer و ذخیرهٔ موجود؛ تغییر فقط برای نیاز مشخص Live با حفظ مصرف‌کنندگان دیگر |
| `dbimport/`, `dbtables/`, `analysis/`, `satellite/`, `publish/`, `restapi/`, `survey/` | مالک منطق هر قابلیت؛ adapter Live منطقشان را دوباره نمی‌نویسد |
| تازه: `live/tests/` | تقسیم تست فعلی به پروژه، نشست، API و جریان‌ها؛ فایل `live/tests.py` هم‌زمان با package هم‌نام باقی نماند |
| تازه: `tests/browser/live/` | سناریوهای مرورگر روی حساب و دادهٔ آزمایشی؛ بدون اثر بر حساب واقعی |

قراردادهای رابط پیشنهادی، پیش از شروع مرحلهٔ ۲ در آزمون‌ها تثبیت می‌شوند:

- `LiveClient.request(url, {method, body, signal})`: پاسخ JSON یا خطای ساخت‌یافته؛ خطای `auth_required` به مسیر ورود می‌رود، HTML به‌جای JSON خطای قابل فهم است.
- `LiveState`: پروژه و لایهٔ انتخابی با شناسه، revision تغییرات و snapshot آخرین ذخیره؛ وضعیت جدول و Job جداگانه. `markDirty()` و `markSaved(revision)` جلوی پاک‌شدن تغییر جدیدتر را می‌گیرند.
- `LiveCommands`: فهرست `{id, label, icon, tab, group, requires, execute}`؛ قابلیت و وضعیت انتخاب، enabled بودن فرمان را تعیین می‌کنند.
- `LivePanels.open(id, context)` و `close(id)`: مدیریت focus و حفظ پیش‌نویس؛ مودال همان قرارداد focus/بستن را رعایت می‌کند.
- `LiveProperties.open(layerId)` با draft مستقل؛ `apply()`، `cancel()` و ذخیرهٔ نهایی از چرخهٔ واحد پروژه.
- `LiveWorkflows.open(kind, context)` با نتیجهٔ مشخص `{layersChanged, catalogChanged, jobsChanged}`؛ هر adapter نتیجه را به همان state برمی‌گرداند.
- خطای API پیشنهادی: `{error:{code,message,fields},request_id}`؛ نیاز به ورود `401`، فقدان مجوز `403`، منبع ناموجود/خارج از دامنه طبق سیاست فعلی `404`. سازگاری endpointهای قدیمی با adapter حفظ شود.
